## 0. 范围与约定

**本文定**：切人执行之后发生的事——普通切人与变奏切人怎么区分；变奏动作是哪个、何时开始；延奏何时触发、由谁发出、协奏何时清零、延奏动作怎么执行；切人相关事件的种类与同一 tick 内的顺序；切人对动作本身的影响（"第 nF 后切人结束技能"）；变奏延奏触发帧缺失时的补法。

**本文不定**：切人的调度条件（切人冷却、切人锁，TD-09 §3.5 已定）；协奏怎么攒（TD-06）；buff 怎么响应这些事件（TD-07）；角色特有的多版本变奏、延奏版本选择（TD-08）。

**约定**：帧一律 60fps；"第 f 帧"是世界帧（与事件日志的 `f` 一致）；"局部第 n 帧"是动作自己的局部帧（TD-04 §2）。

### 0.1 要点

1. 切人时看**切出者**的协奏：满（≥ `rules.concertoMax`，100）是变奏切人，否则是普通切人（机制设计 §5.4）。
2. 变奏切人：切入者在同一 tick 开始变奏动作（角色模块别名 `QTE` 指向的动作）。它会取消切入者在后台还在走的动作（TD-04 §4.2 的普通取消）。普通切人不碰切入者的动作，后台动作继续走（总设计不变量 3）。
3. 延奏在变奏动作走到 `outroTriggerFrame` 时触发，由**这次切人的切出者**发出。这一刻按顺序：切出者协奏清零 → `outro` 事件（TD-07 的延奏 buff 在这里挂上）→ 切出者的延奏动作开始。
4. 变奏被取消时，没走到的延奏触发转为尾部，按战斗时钟照常发生（AGENTS.md 差异 1，本文并回）。
5. 延奏动作（椿的"缠绕"等带伤害的延奏）以**独立时间线**执行：不取消、也不被切出者自己的动作取消，只按战斗时钟把判定生成出来。没有延奏动作的角色（散华、维里奈），延奏只有 buff 效果。
6. 新增数据字段 `endOnSwitchOut`："第 nF 后切人（立即）结束技能"的动作，在切出时若已走到局部第 n 帧，按取消处理。M0 队伍用到的是椿 A4（72）与盛绽·A3循环聚怪（24）。
7. 同一 tick 的顺序：`switch` 事件 → 切出者的 `switchOut` 触发点（挂在它身上的 `onSwitchOut: clear` buff 移除、`endOnSwitchOut`）→ 切入者的 `switchIn` 触发点 → 变奏时 `actionStart`（QTE；其后按 TD-06 §7 发施放资源）→ `intro`。`switchOut` / `switchIn` 由 `switch` 事件派生，不另记事件（§6）。

## 2. 切人执行

TD-09 §3.5 已经定了切人的调度条件和"换前台、启动切人冷却"，然后调用 `onSwitch(s, k, from, to, cmd)`。本文定义 `onSwitch` 做什么（`switch` 事件改由它记，这样 `intro` 字段在记之前就算好，TD-09 §3.5 相应修订）：

```text
onSwitch(from, to):
  intro = from.concerto ≥ rules.concertoMax 且 to 有变奏动作
  记 switch 事件（from、to、intro、cmd）
  ① 切出者的 switchOut 触发点：
     - 挂在 from 身上的 onSwitchOut = clear 的 buff 移除（TD-07 §8）；其余 switchOut 触发
     - from 当前动作带 endOnSwitchOut 且局部帧 ≥ 它 → 按取消处理，by = '切人'（§5）
  ② 切入者的 switchIn 触发点：
     - 挂起的 nextIn buff 施加给 to（TD-07 §3）；其余 switchIn 触发
     - intro：startAction(to, 变奏动作)，记 outroLinks += { introInstance, from }，intro 事件
```

- **协奏在延奏触发时清零，不在切人时**（总设计不变量 5）。切人到触发帧之间，切出者在后台命中攒到的协奏也一并清掉。
- **变奏动作的开始不走合法性检查**：它由切人触发，优先级 11，不等就绪、不看冷却与资源。切入者在后台还在走的动作按 TD-04 §4.2 取消：没出现的判定作废，已出现的可脱手判定照常生成。
- **普通切人**：切入者的后台动作继续（不变量 3）；切人后同一 tick 就能出招（TD-09 Q5 维持）。
- **切入者没有变奏动作**（模块既没有别名 `QTE`，也没有 id 为 `QTE` 且 `kind = 'intro'` 的动作）：按普通切人处理，协奏不清零，记一条 `warning`。
- **同一 tick 的顺序**：`switch` → `switchOut` 触发点 → `switchIn` 触发点 →（变奏时）`actionStart` → 施放资源（TD-06 §7：QTE 的协奏、核心资源）→ `intro`。TD-07 的触发按这个顺序处理，所以"切人时…"的 buff 先于"施放变奏技能时…"的 buff。
- **变奏动作的 `actionStart` 带这条切人指令的出处**（`cmd`）：统计窗口按它算（TD-09 §3.9），轴的最后一条是变奏切人时，窗口到变奏动作（及其接续动作，TD-08 P10）结束。

### 2.1 变奏动作是哪个

- 角色模块别名 `QTE` 指向的动作；没有这个别名时取 id 为 `QTE`、`kind = 'intro'` 的动作。
- 同一角色有多个变奏版本的（守岸人 QTE / 强化QTE 等）按条件选哪个，v0.1 不支持，别名指向默认版本（Q1）。
- 变奏由多个动作组接续组成的（维里奈：QTE-冲 命中后接 QTE-撞），接续由 TD-08 的 `followUp` 写法完成；本文只关心第一个组，它带 `outroTriggerFrame`。

## 3. 延奏的发出与对应关系

一次变奏切人把"哪次变奏 → 由谁发延奏"记进状态：

```ts
// SimState 新增（TD-02 §7.2）
outroLinks: { introInstance: number; from: Slot }[]   // 变奏动作实例 → 延奏的发出者（这次切人的切出者）
```

- 延奏触发时（§4）按 `EventSource.instance` 查出发出者，用过即删。
- 查不到（测试台直接开始变奏动作，TD-09 §4.1）：不触发，也不报错。
- 切出者在触发前又被切回前台（切人冷却 60 帧，而触发帧最晚 71 帧，理论上可能）：照常触发，协奏照常清零。

## 4. 延奏触发

### 4.1 时刻

- 变奏动作局部帧走过 `outroTriggerFrame`（TD-04 时间线的 `outro` 事件 → `hooks.outroTrigger`）。
- **变奏被取消时**：没走到的延奏触发转为尾部，按战斗时钟继续，照常发生（TD-04 §4.2 修订，AGENTS.md 差异 1）。延奏触发也不挡"就绪"（TD-04 §6.4 修订）。例：散华 QTE 第 42 帧被大招强制打断，延奏在变奏的局部第 53 帧（按战斗时钟）触发；大招的全局时停期间战斗时钟不走，所以世界帧要晚 90 帧（T05-3）。
- **区间写法**（灯灯、珂莱塔）：构建脚本从备注"第 a～bF 触发上一角色延奏"取 a 作为 `outroTriggerFrame`，行上打 `outroRange`（TD-01 §3.8 修订）；角色模块可覆盖。
- **"立即触发"**：0；**没写**：0，打 `noOutroFrame`。

### 4.2 触发时做什么（同一 tick，按顺序）

1. **切出者协奏清零**：`resource` 事件，`cause: 'outro'`（TD-06）。
2. **`outro` 事件**（`char` = 切出者，`to` = 这次变奏的角色）：TD-07 的 `trigger: { on: 'outro' }` 在这里触发。`target: 'nextIn'` 的延奏 buff 挂到 `to` 身上（散华延奏"下一位登场角色普攻伤害加深 38%"挂给椿）。延奏动作的独立时间线在记这条事件之前就建好，事件带它的实例号 `instance`，钩子可以在这里挑版本（TD-08 P5）。
3. **延奏动作开始**（有的话，§4.3）：在 `outro` 的触发与钩子处理完之后发它的施放资源（跳过的版本不计入协奏，TD-06 §3.2）。

### 4.3 延奏动作：独立时间线

- **延奏动作是哪个**：角色模块别名 `延奏` 指向的动作；没有别名时取 id 为 `延奏`、`kind = 'outro'` 的动作；都没有 → 延奏只有 buff 效果。
- **执行方式**：把延奏动作的整条时间线（判定生成、施放资源、按动作登记的膨胀）作为切出者的一条**独立尾部**（`TailRuntime.detached = true`），局部帧从 0 起按战斗时钟推进（TD-04 §4.4）。局部第 0 帧就是触发的那个 tick：它在本 tick 的 P3 里出现，排在 P3 最后推进。
- **持续帧 −1 的判定不生成**（"直到动作结束"）：延奏动作不是进行中的动作，同 TD-04 §4.3 自然结束的规则。
- **不取消切出者当前的动作**：延奏是切出者"离场时发出的效果"，它在后台的动作照常走完（不变量 3 的延伸）。
- **不被切出者之后的动作取消**：TD-04 §4.2 的"变更动作时此前留下的不可脱手判定一并消失"不作用于独立尾部，也不作用于它生成的判定（`JudgmentRuntime.detached`）。
- 按动作登记的膨胀、判定的攻击顿帧：敌人侧、队友侧照常登记；**自身侧不登记**（切出者此时不在做这个动作；TD-04 §5：自身侧只作用于仍在进行的出招动作）。
- 延奏动作的判定按正常判定结算：伤害（TD-03；椿的延奏 dmg 倍率为 0，按技能说明手填，TD-08 §5.2）、资源（TD-06）、触发（TD-07）。
- **版本**：椿的延奏组里有普通 / 含苞 / 含苞追加三个版本，全生成会算三次。由角色钩子在 `outro` 事件里用 `ctx.skipJudgments` 去掉不适用的版本（TD-08 §4 模式 P5）。

## 5. 切人对动作本身的影响

总设计不变量 3："切人不打断动作"。少数动作的备注写明切人会结束它，本文把这一类做成数据：

```ts
// ActionDef 新增（TD-02 §4）
endOnSwitchOut?: Frame      // 切出时当前动作局部帧 ≥ 它 → 按取消处理（by = '切人'）；0 = 切人立即结束
```

- **来源**：构建脚本从备注抽 `hints.endOnSwitchAfter`："第nF后切人（立即）结束技能"、"第nF后切人消失" → n；"切人立即结束 / 消失" → 0（TD-01 §3.8 修订）。装配成 `ActionDef.endOnSwitchOut`；角色模块可覆盖。
- **处理**：切出时（§2 ①），切出者当前动作的局部帧 ≥ `endOnSwitchOut` → 按 TD-04 §4.2 取消：没出现的判定作废，已出现的可脱手判定照常生成，没发生的资源与膨胀作废；日志 `actionCancel`，`by: '切人'`。局部帧还没到 → 动作照常在后台走完。
- **M0 队伍**：椿 A4 "第72F后切人立即结束技能"（长按 20 段；在前台转到第 72 帧后再切走，剩下的段不打）、盛绽·A3循环聚怪"第24F后切人结束技能"。
- **不在本文实现**（Q6）："第nF前切人不消失 / 不离场"（陆·赫斯、赞妮、露帕）、没有帧数的"不能切人"（118 组，多为谐度破坏的无敌期）。仍按"切人不打断、没有锁"。

## 6. 接口与类型

```ts
// src/engine/switch.ts —— TD-05：切人之后的事（sim = 一次仿真的运行环境：装配结果、buff 登记表、内核、事件队列，src/engine/context.ts）
/** TD-09 的 onSwitch：调度器换完前台、启动切人冷却之后调用；switch 事件由它记（§2） */
export function onSwitch(sim: Sim, s: SimState, from: Slot, to: Slot, cmd: CommandRef): void

/** TD-04 的 hooks.outroTrigger：变奏动作（或它的尾部）走到 outroTriggerFrame；slot = 变奏的角色 */
export function outroTrigger(sim: Sim, s: SimState, slot: Slot, src: EventSource): void

/** 变奏动作 / 延奏动作是哪个（§2.1、§4.3） */
export function introOf(m: ResolvedMember): ActionDef | undefined
export function outroOf(m: ResolvedMember): ActionDef | undefined
```

类型改动（TD-02）：

| 位置 | 改动 |
|---|---|
| `SimState` | 新增 `outroLinks: { introInstance: number; from: Slot }[]` |
| `TailRuntime` | 新增 `detached?: true`：延奏动作的独立时间线，不受持有者之后的动作影响 |
| `JudgmentRuntime` | 新增 `detached?: true`：由独立时间线生成的判定，持有者开始新动作时不清掉 |
| `ActionDef` / `ActionOverride` | 新增 `endOnSwitchOut?: Frame` |
| `HintsSchema` | 新增 `endOnSwitchAfter?: number`；`outroTriggerFrame` 也从区间写法取起点 |
| `SimEvent` `outro` | 新增 `to: CharName`（这次变奏的角色，`nextIn` 的去处）与 `instance?: number`（延奏动作那条独立时间线的实例号，给钩子挑版本，TD-08） |
| 内核（TD-04） | `cancelAction` 导出（`by` 可以是 `'切人'`）；`spawnJudgment` 多一个 `detached` 参数 |

事件沿用 TD-02 已有的 `switch`（`intro` 字段）、`intro`、`outro`、`actionCancel`（`by: '切人'`）。`switchIn` / `switchOut` 不另设事件：TD-07 从 `switch` 事件的 `from` / `to` 派生。

## 7. 边界情况

| 情形 | 处理 |
|---|---|
| 变奏切人时切入者在后台还有动作 | 取消（TD-04 §4.2），日志 `actionCancel`，`by` = 变奏动作 |
| 变奏动作被大招等打断（散华 QTE 第 42 帧起） | 延奏照常在局部触发帧发生（尾部，按战斗时钟） |
| 变奏未到触发帧又切人（切入者再被切走） | 变奏动作转后台继续，延奏照常触发；新的这次切人按它自己的协奏判定 |
| 延奏触发前，切出者的协奏被消耗（如椿一日花） | 触发时照样清零（清零是"设为 0"，不是"减 100"） |
| 两次变奏切人的延奏触发落在同一 tick | 按变奏角色的槽位 0 → 2 处理（TD-04 §1 同相位顺序） |
| 切出者协奏满、切入者没有变奏动作 | 普通切人，协奏不清零，`warning` |
| 场景 `initial.concerto` 让开场的前台角色协奏已满 | 与战斗中攒满相同；第一次切人就是变奏切人 |
