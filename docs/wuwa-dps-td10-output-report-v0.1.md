## 0. 要点

1. 所有数字都从事件日志派生（总设计 §3.5），不在别处重算。
2. **稳态取完整的轮**：第 2 轮到倒数第 2 轮。第 1 轮受开局资源影响，最后一轮没有下一轮的边界、偏高（§2）。
3. **对比**：把场景改几处、各跑一次再做差；有分轮时比稳态，"差在哪"按窗口内的**每秒伤害**拆到角色与动作，再看 buff 覆盖率与面板（§3）。
4. **副词条边际**：每种副词条各加一档（缺省各档平均）、重跑比稳态 DPS（§4）。轴是固定的。

## 1. 汇总 `Summary`

| 字段 | 含义 |
|---|---|
| `totalDamage`、`windowFrames`、`dps` | 统计窗口内的总期望伤害、窗口长度（战斗帧）、DPS = 伤害 ÷ 窗口秒数 |
| `overflowDamage` | 窗口外仍在结算的伤害（残留的领域、召唤物），不计入 DPS |
| `byChar`、`byAction` | 窗口内按角色、按动作（角色 + 动作 ID）的伤害与占比 |
| `resourceTimeline` | 每 `rules.sampleInterval` 个世界帧采一次三人的能量与协奏（TD-06 §6.1） |
| `buffUptime` | "buff→目标" → 窗口内存在的比例（TD-07 §10.1） |
| `waits` | 不是写轴要求的等待（TD-09 §3.3） |
| `warnings` | 装配与仿真中的提示 |
| `perLoop?`、`steady?` | 分轮与稳态（§2，`options.repeat ≥ 2`） |

**统计窗口** = [第 0 帧, 最后一条指令的完成时刻)（TD-09 §3.9），按战斗帧；`options.endAt` 可覆盖。战斗帧 < 窗口终点的伤害计入，其余是窗口外。

## 2. 分轮与稳态

- **每一轮** = [本轮 `loop` 事件, 下一轮 `loop` 事件)；最后一轮到统计窗口终点（TD-09 §3.7：等下一轮起手的时间算在上一轮里）。
- `perLoop[k]`：`loop`、`start`（战斗帧）、`frames`、`damage`、`dps`，三人的 `energyDelta`、`concertoDelta` = 下一轮开始时（最后一轮：窗口终点）− 本轮开始时。资源按日志从初始值重放（同 `resourceTimeline`）。首尾差都是 0 说明这条轴能自给。
- `steady`：第 2 轮到倒数第 2 轮合起来的伤害 ÷ 时长（`from`、`to`、`frames`、`damage`、`dps`）；只有 2 轮时取第 2 轮。
- **为什么不取最后一轮**（总设计 v0.1.5 原写"稳态以最后一轮为准"）：最后一轮没有下一轮的边界，等能量、等冷却、轮首的 `wait` 都算不进来，DPS 偏高。M0 代表轴循环 4 轮：第 1 轮 25,238，第 2、3 轮都是 26,061（资源首尾差 0），第 4 轮 26,722。
- **写法**：轴的结尾要回到第 1 轮开头的局面（M0 代表轴结尾 `switch 维里奈`），`options.repeat` 4 左右、`maxFrames` 相应放大。

## 3. 对比 `compareRuns`

**口径** `basisOf`：有分轮取稳态，否则取整个窗口；记为 [lo, hi)（战斗帧）。

**差在哪**：

| 项 | 怎么算 |
|---|---|
| DPS | 对比 − 基准，及百分比 |
| 分角色、分动作 | 窗口内的**每秒伤害**（伤害 ÷ 窗口秒数），同一个窗口里加起来就是 DPS；两边窗口长短不同（换了声骸、轴变快）也能比。按差额绝对值排序 |
| buff 覆盖率 | 各自的窗口内算（`buffUptime(log, lo, hi)`），标记型 buff（计时、状态）不列 |
| 面板 | 攻击、暴击、暴伤、共鸣效率（含常驻的共鸣效率 buff）；常驻的其他 buff 在命中时才叠，不在面板里 |

**命令**：`pnpm compare 基准.yaml 对比.yaml`。打印两边的口径与 DPS、差额，变化了的面板，分角色、分动作（差额前 12）、buff 覆盖率（差 ≥ 1 个百分点，前 12）。场景有错或运行出错时退出码 1。

例（2026-10-04，M0 代表轴）：椿首位异相·无妄者换梦魇·无冠者（词条不变），稳态 DPS 26,061 → 29,850（+14.5%）：首位加成湮灭 / 普攻各 +12%（覆盖率 0 → 100%），它的 Q 只要 39 帧（无妄者 123 帧），两轮共 70.80 → 66.23 秒。

## 4. 副词条边际 `marginal`

- **一档**：`echo-stats.json` 的 `subTiers`（TD-01 §12.6），缺省取各档平均（比例取到 0.0001，固定值取整：暴击 8.4%、暴伤 16.8%、攻击% 9.0%、攻击 +50、生命 +450…），`--tier max` / `min` 取最高 / 最低档。
- **加在哪**：该角色**最后一件声骸**的副词条上（不动首位；场景必须至少有一件声骸）。
- 13 种副词条各重跑一次，按 DPS 增加从大到小排。
- **轴是固定的**：共鸣效率只在原来要等能量时才有收益；"效率够了能把轴排得更紧"要改轴，属于轴搜索（总设计 M7）。只影响队友 buff 的角色（维里奈），自己的副词条收益很小是正常的。
- **命令**：`pnpm marginal 场景.yaml [--char 角色] [--tier avg|max|min]`，不写 `--char` 时三人都算。M0 代表轴（4 轮）每次约 0.3 秒，一个角色 14 次。
- 例（2026-10-04，椿）：暴击 +6.2% > 暴伤 +4.5% > 攻击% +2.8% > 普攻加成 +2.5% > 攻击 +1.5% > 共鸣解放 +0.3%；共鸣技能、重击加成为 0（她的 E、重击打的是普攻伤害），共鸣效率为 0（这条轴不等能量）。

## 5. 命令行

| 命令 | 输出 |
|---|---|
| `pnpm sim 场景.yaml [--out 日志.json]` | 队伍面板、敌人；窗口、总伤害、DPS（窗口外伤害）；分轮表（循环时）；分角色、分动作；不是写轴要求的等待；提示；事件日志写到 `out/<场景名>.json` |
| `pnpm compare 基准.yaml 对比.yaml` | §3 |
| `pnpm marginal 场景.yaml [--char 角色] [--tier …]` | §4 |

共用的读场景、对齐、数字格式在 `src/cli/format.ts`。退出码：0 成功；1 场景有错或运行期报错；2 用法错误。
