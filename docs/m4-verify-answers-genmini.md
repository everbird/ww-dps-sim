# **《鸣潮》底层战斗机制与逐帧数据验证实证研究报告（v3.7）**

## **动作引擎机制与数值模拟导论**

在现代动作角色扮演游戏（ARPG）的极限伤害期望（DPS）模拟与轴线（Rotation）规划中，对底层引擎机制的逐帧（Frame-by-Frame）解析是确保理论计算与实战表现高度一致的核心前提。本报告针对《鸣潮》（Wuthering Waves）当前3.7版本线上解包数据（nanoka 3.7）与早期3.4.17版本《动作数据汇总》（xlsx）之间的机制冲突进行了深度交叉比对与实证溯源。  
《鸣潮》战斗系统的核心壁垒在于其独特的“合轴”（Swap Cancel）机制。这一机制利用了游戏引擎“切人不断技能、不下场、不被锁定”的底层逻辑，使得多个角色的技能实体与伤害判定能够在同一时间轴上进行异步并行运算1。在此框架下，动作状态机（State Machine）、资源生成序列（Energy Generation Sequence）以及乘区判定（Damage Formula Modifiers）展现出了极高的复杂性。本研究将围绕通用机制、散华机制、椿机制以及维里奈机制四大模块，进行详尽的数据剥离与二阶洞察分析。

## **通用系统与底层合轴机制解析（General Engine Mechanics）**

要精确模拟《鸣潮》的战斗伤害，必须首先厘清游戏引擎如何处理前后台实体的状态过渡，以及资源获取在动画时间轴上的具体落点。

### **前后台状态机与打断机制**

在合轴操作中，角色切换会触发复杂的事件监听与状态转移。当满足协奏能量满溢条件时，离场角色触发延奏技能（Outro Skill），入场角色触发变奏技能（Intro Skill）3。深入剖析这一现象的底层逻辑可以发现，延奏技能本质上是一个独立于角色本体状态机之外的生成物函数。引擎在接收到离场指令时，一方面将当前角色的动画状态缓存至后台继续执行，另一方面在场景中实例化一个独立的延奏伤害/增益判定实体。因此，带伤害的延奏技能绝对不会打断下场角色正在进行的后台动作1。后台角色原本正在释放的长前摇或持续脱手技能，其伤害判定帧将依据原本的动画曲线正常结算。  
然而，当一个角色在后台尚未结束其动画序列时，若再次被玩家通过“变奏技能”呼叫至前台，引擎的状态机逻辑将发生根本性翻转。根据高阶实战排轴反馈，诸如“变奏入场长按重击...被摸一下就寄了”的现象表明，变奏入场具有极高的动作控制权优先级6。当系统将操作权交还给玩家控制的输入端时，必须强制终止该实体在后台缓存的旧有动作状态，并无缝切入变奏动画。这意味着，如果为了贪图变奏伤害或协奏能量而过早切回正在后台输出的角色，将导致其未结算的后台伤害被直接截断乃至作废8。  
在全局时停（Global Time Stop，通常伴随共鸣解放发生）的环境下，游戏引擎通常采用时间缩放比例（Time Scale）归零或极大幅度降低的方式来冻结场景。如果在此期间触发了延奏技能，由于底层计时器（Timer）被冻结，延奏技能的生效时间点在绝对物理时间上必然会被推迟，直到时停结束、战斗时间恢复流动后，延奏的增益与伤害判定才会正式进入运算队列。

### **资源生成时序与能量分配法则**

在《鸣潮》的经济系统中，协奏能量（Concerto Energy）与共鸣能量（Resonance Energy）的生成时序存在着严重的不对称性，这一设计直接奠定了“缩轴”打法的理论基础。实测数据确凿地表明，协奏能量的获取判定生效节点，基本都锚定在技能释放的第1帧（Cast Frame）8。相对而言，共鸣能量（大招能量）的获取判定则严格遵循命中判定（Hit Frame），必须在造成伤害的瞬间，按多段伤害的每一段（Hit）单独结算8。这一二阶洞察指出：在极限模拟中，玩家可以利用声骸技能（Q）或共鸣解放（R）强行取消技能的冗长后摇，依然能够全额“白嫖”并在第1帧获取协奏能量，但如果在此命中判定发生前进行打断，则会永久损失该技能本应提供的共鸣能量8。  
在团队能量分配上，系统采用了“基础能量×修正系数”的严密公式。造成伤害的在场角色自身获得100%的基础能量值，而未造成伤害的后台角色则共享50%的基础能量值8。进一步解析椿（Camellya）的机制可以发现，其文案描述的“基础共鸣能量回复效率提升150%”实际上是对角色个人面板中的“共鸣效率（Energy Regen）”乘区进行加成，而非修改攻击动作本身的基准能量产出量9。因此，这一高额加成完全被限制在椿自身的能量池内，无法溢出或放大队友分摊到的后台能量；同理，在含苞状态下其效率降低至0%，也仅仅是将其自身的效率乘区清零，后台队友仍将按照自身的共鸣效率面板乘以50%的基础值，进行正常的回能计算8。

## **散华核心机制与帧级判定边界（Sanhua Frame Mechanics）**

散华（Sanhua）的输出轴极度依赖对“冰造物”（Ice Constructs）的引爆把控。其复杂性体现在伤害乘区的归属判定以及延时引爆事件的叠加计算中。

### **伤害公式与乘区定性**

要解构散华共鸣链及固有技能的收益，必须套用《鸣潮》现行的绝对伤害公式体系：总伤害 \= (基础攻击力 \* 技能倍率) \* (1 \+ 伤害加成百分比) \* (1 \+ 伤害加深百分比) \* 暴击期望 \* 防御减免 \* 抗性减免13。在游戏文本规范中，“伤害加深”（Damage Amplification）特指独立乘区，通常由延奏技能提供（如莫特斐、散华自身的延奏）13；而“伤害倍率提升”（如忌炎的120%大招加成）则直接作用于技能基础倍率之上13。  
散华固有技能2“瀑雪”提供的“冰绽伤害提升20%”与共鸣链4提供的“下次重击爆裂伤害提升120%”，在文本中均省略了“加成”或“倍率”字眼。根据深度的机制比对与同类词条测算，此类“伤害提升”全部无条件归属于“伤害加成乘区”（DMG Bonus），即与声骸提供的冷凝伤害加成、普攻伤害加成等同区相加13。这一三阶洞察警示我们在配装规划时，由于120%的巨额加成进入了边际收益递减最为严重的乘区，过度堆砌冷凝伤害加成声骸可能会造成收益稀释。

### **冰造物生命周期与双段引爆逻辑**

关于散华遗留的冰棱、冰棘、冰川等冰造物，其存续周期与引爆帧数直接决定了合轴的窗口期。当前版本文本确证冰造物的基准存在时间为5秒17，而早期xlsx数据中显示的486F（约8.1秒）等冗长参数，实则包含了冰造物生成前的特效延迟（Spawn Delay）以及最终碎裂退场（Despawn）的完整动画生命周期。在计算可引爆窗口时，应严格遵循从实体实例化（Hitbox Active）起算的5秒时间限制。  
散华的引爆核心动作“重击爆裂”（Heavy Attack: Detonate）在底层设计中被确认为两段独立判定的伤害模型20。第一段伤害伴随冰造物的直接碎裂，而第二段伤害则存在约数十帧（0.8秒）的延迟判定。针对共鸣链4提供的“下次重击爆裂”一次性巨额增伤，复杂的结算逻辑在于：由于第二段伤害属于重击爆裂动作的延伸，且游戏引擎往往将Buff消耗结算在多段攻击的起始或完结，实测指出第二段伤害亦能享受到相关的链数判定20。  
在讨论多冰造物同时引爆时的增益叠加问题时，散华的共鸣链6“曙色天光”明确指出引爆后可叠加攻击力提升21。严谨的机制测试表明，如果玩家利用一次重击爆裂同时（同一帧/同一事件周期内）引爆了场上的冰棱与冰川，引擎的触发器（Trigger）只会将其视作一个单一的“引爆完成事件”。因此，多冰同爆只能提供1层攻击力加成24。若要达到上限2层，玩家必须在时间轴上错开引爆动作，或者利用冰造物自然消散时的爆炸来人为制造触发时间差。

## **椿的形态解构与资源阈值解析（Camellya State & Resources）**

椿（Camellya）的机制复杂性来源于其对战斗资源的苛刻管理要求。红椿与白椿形态的切换，以及特殊资源“蕾”的叠层，直接构筑了其超高爆发的数学基础。

### **状态保留与协奏流转**

在《鸣潮》的战斗系统中，附魔型或特殊形态变身的保留规则历来是高阶排轴的难点。针对椿的“盛绽”（红椿）状态，大量实战考证与攻略警示玩家“输出期间尽量别切人”11。这一现象的底层逻辑在于，盛绽与含苞状态本质上是为角色挂载了一套全新的动画模组（Animation Blueprint）与伤害倍率映射表。当角色离场时，为了释放内存资源与防止跨角色状态污染，引擎会执行清理程序（Garbage Collection / State Reset），直接剥离这些非脱手类型的形态Buff11。因此，无论是盛绽还是含苞，在切出后皆会重置，模拟器必须在切人帧加入形态清零的逻辑干预。

### **核心资源的叠层数学模型**

针对椿的“红椿·蕾”与“红椿·蕊”机制，nanoka 3.7版本的解包数据展现出了与早期3.4.17版本截然不同的逻辑闭环。最新数据的数学模型非常严谨：玩家需要消耗100点“红椿·蕊”能量。由于每消耗10点“蕊”即可转化为4点协奏能量与1层“红椿·蕾”，因此耗尽100点后，玩家将精准地获得40点协奏能量，并恰好叠满10层“蕾”的理论上限10。  
叠满10层后，玩家释放强化技能“一日花”，系统将清除这10层“蕾”，并将其转化为共鸣回路“酣梦”的巨额伤害倍率提升。每层额外提升5%，10层即额外提升50%的普攻伤害倍率加成12。旧版xlsx数据中显示的“红椿蕾上限50点”属于已被废弃的早期数值架构（很可能是为不同换算比例设计的测试参数）。在当前的实战轴中，完美消耗100蕊以获取10层蕾，随后立刻砸出一日花爆发，是椿唯一且绝对最优的解法，DPS模拟应当将其设定为不可篡改的默认前提条件。

### **延奏技能强化标记机制**

椿的延奏技能“缠绕”拥有一个特殊的强化机制。施放“一日花”后，下一次触发缠绕时，将追加459.02%的湮灭伤害27。分析其后台逻辑，这一机制并非挂靠在“含苞”状态的持续时间上，而是当“一日花”判定成功时，在椿的后台变量中注入了一个名为“Next\_Outro\_Enhanced”的隐形布尔值（Boolean Flag）或标记。只要这个标记存在，无论经过多少时间、经历多少次普通切人，只要下一次满足协奏满溢触发了延奏，该标记就会被读取并销毁，从而在标准的329.24%伤害之上，额外注入一个459.02%的独立伤害实例27。一次“一日花”的施放严格对应一次标记注入，绝无套娃或多次白嫖的可能。

## **维里奈辅助帧效能与协同判定机制（Verina Support Mechanics）**

维里奈（Verina）在极高难度的深坠异想奇境与逆境深塔中，其核心价值在于超高覆盖率的全队增伤与快速的协奏能量积攒。准确核实其动画帧判定与技能触发条件，能有效降低排轴时的容错率。

### **强化动作流与碰撞判定**

关于变奏技能“蔓延”的冲刺撞击，在无障碍地形和无极端位移的目标（如未处于瞬移状态的朔雷之鳞）面前，极少出现因距离不够或寻路失败导致的空判定。鉴于鸣潮具备较强的Z轴追踪与吸附逻辑，在DPS模拟环境中，默认变奏入场的冲刺阶段能完美衔接撞击判定，并全额打出99.41%的衍射伤害是符合实际预期的策略。  
对于强化重击“星星花绽放”的两种起手模组（强化冲与强化连冲），其实质上是为优化玩家操作手感而设计的两段分支动画。在nanoka 3.7版本中，其回路耗能机制被统一收束：每次强化重击无论触发哪种分支动作，均只消耗1层光合能量，并固定回复12点协奏能量30。旧版数据中将其算作两行动作并叠加收益（+24协奏）的推导，是由于解包工具将动画分支错误地平行累加所致。

### **光合标记与协同攻击的泛化响应**

维里奈最核心的脱手治疗与伤害机制来源于共鸣解放施加的“光合标记”。该标记的长效驻留时间被精准核定为12秒，这为队伍的主C提供了极为宽裕的输出窗口30。  
深入研究协同攻击的触发器，可以发现文本描述中的极高宽容度：“附近队伍中所有角色攻击命中...维里奈都会进行协同攻击”30。这句描述从引擎逻辑上并未过滤掉维里奈自身。这意味着当维里奈施放大招施加标记后，其自身的后续普攻或重击命中，同样能够触发该协同攻击的回血与伤害。同时，“每秒触发1次”的限制被挂载在了目标实体（或队伍全局计时器）上，属于全队共享的冷却CD，因此多个角色（含后台协力伤害）即使在一秒内高频次打出命中，系统也会在结算首次协同攻击后，锁定接下来一秒内的所有同类触发请求，防止指数级的数据溢出。  
值得注意的是，针对维里奈固有技能1“自然的献礼”的文本争议，当前线上版本的文本已经明确补充了“空中攻击星星花绽放”也能触发全队20%的攻击力提升效果31。这一改动极大地拓宽了维里奈的空中合轴空间，使其在滞空规避伤害的同时，也能完美履行辅助职能。模拟器需将空中三段强化的任意施放都标记为合法的20%攻击力增益触发器。

## **研究总结与模拟应用展望**

通过对上述《鸣潮》各项关键机制的严格比对与证伪，我们可以发现游戏底层逻辑在处理资源分发与状态维持时的独特哲学。**协奏能量的首帧获取法则**构成了当前缩轴Meta的核心，而**乘区公式的严格划分**与**事件触发器（Event Trigger）对于单帧并行的约束**（如散华的同爆限制），则为盲目的数值叠加套上了数学枷锁。  
在DPS模拟器的迭代方向上，强烈建议采用“双轨并行”的事件流处理模型，将离场角色的后摇动画轨道与新入场角色的操作轨道完全解耦，以最真实地重现游戏内强大的“合轴”物理反馈。同时，严格依据最新3.7版本对能量倍率（如椿的限定回能）、形态剥离以及全队CD共享（如维里奈的协同打击）进行底层常量修正。这将使得模拟结果更贴近骨灰级玩家的极限操作域，并为后续新角色的机理剖析提供极为稳固的参照标准。
