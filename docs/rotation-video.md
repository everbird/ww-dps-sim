# WuwaLAB 怎么分析一条轴、和我们比；视图 E 的视频对照（2026-10-22）

## 1. WuwaLAB 的轴页（以 [rotation/49](https://wuwalab.com/rotation/49) 为例）

读的是页面背后的接口 `api.wuwalab.com/api/app/rotation/49`（1.2 MB JSON）和页面的打包代码。这条是"20 Nightfall"：赞妮 · 菲比 · 千咲，三人都是 6 链、专武精炼 5，作者アント・クラッシャー，状态"verified"。

**数据长什么样**：
- **一条轴 = 一行行动作**（这条 262 行，2 分钟）。每行写：
  - 谁、哪个技能；
  - 从第几帧开始（`frame`）；
  - **怎么结束**：取消方式与第几帧（`cancel`：普通 / 闪避 / 无敌取消，`cancelFrame`），或第几帧切人（`swapFrame`，88 行有）；
  - 这一行之后的协奏、能量、伤害，各命中的伤害类型。
- **每行都存一份状态快照**（用下标指到几个池子里）：
  - 共鸣回路（`fortePool`）；
  - 敌人：减防、偏谐、异常效应层数与下次结算（`enemyPool`）；
  - 身上的 buff 与剩余时间（`buffPool`，自己的、队友给的分开）。
- **两个榜**：
  - 2 分钟 DPS：整段 7200 帧，含开局；
  - 循环 DPS：作者在轴里**手动标一段循环**（第 92–150 行，1614 帧），只算这段。
  - 另有按"角色 × 伤害类型"的拆分、异常效应的统计（光噪：24 次、平均、最大）。
- **共鸣效率**：每人"要几条共鸣效率副词条 / 要不要主词条"，按平均和高练度两套配装各算一次。还可以逐人切换"高练度 / 平均配装"（`mixes`），看榜上的数怎么变。
- **审核**：作者附视频，管理员对着视频核过才标"verified"。

**视频**：只是右侧栏的一个嵌入（YouTube 用 nocookie 嵌入，B 站用官方播放器），点了才加载，**和轴不联动**：没有时间对应，也不读播放进度。

## 2. 和我们比

| | WuwaLAB | 我们 |
|---|---|---|
| 轴怎么写 | 一行一个动作，**取消点、切人帧由作者填**（作者已经知道在哪取消） | 写指令（`椿 E A A`、`switch 散华`），**调度器按数据算最早合法帧**（优先级、派生窗口、切人锁、冷却、资源），等了会写原因 |
| 帧数据 | 社区实测（含命中顿帧） | 解包 xlsx（不含顿帧），WuwaLAB 当第二来源核对（`pnpm crosscheck:wuwalab`） |
| 每一帧的状态 | 每行一份快照 | 逐帧都有（视图 D、E 的检查器），资源、buff、冷却、敌人量表、共鸣回路 |
| DPS 口径 | 2 分钟、手动标的循环段 | 稳态（多跑几轮、去头去尾，带误差条和漂移提示）、打死几倍血、前 N 秒（`goal`） |
| 不确定的地方 | 不显示 | 假设表、敏感度矩阵、"轴可能有问题"、卡帧点、手速档 |
| 配装 | 两套固定配装（平均 / 高练度） | 按你的账号库存、边际、择优 |
| 和实战对 | 管理员看视频人工审核 | 视频时间点（`video.marks`，`pnpm trace` 列仿真比视频快慢），现在加了视图 E 的视频对照 |
| 视频 | 侧栏嵌入，不联动 | 见下一节 |

**值得借的**：
1. **取消方式当作轴的一部分**。WuwaLAB 让作者写明这一下怎么取消（普通 / 闪避 / 无敌）、第几帧切人；我们是"最早合法帧"自动算。两种各有用：自动算能找出最优，手填能复现视频里实际的打法。我们已经有 `+N`、`!`、`wait`，缺的是"这一下用闪避取消"这种写法。先记下，不做。
2. **只算轴里标出的一段循环**。和我们的稳态（自动挑轮）是两种口径；有开局很长的轴时手动标更直观。不急。
3. **审核状态**（"对着视频核过"）就是我们的校准。我们的视频对照做出来后，可以给场景打"核过哪几段"的标记。

**不需要借的**：两套固定配装（我们按你的账号算）；快照式存状态（我们逐帧都有）。

## 3. 视图 E 的视频对照（原型）

`pnpm timeline <场景> --view e`，或网页"场景"页运行后切到视图 E，点控制条上的"视频"。

**做法**：
- 视频按真实时间录，对应仿真的**世界帧**（大招动画也在里面），60 帧一秒。
- **锚点**：一个锚点就是"视频里的这一刻 = 仿真的这一帧"。
- 换算有两种方式（`web/designs/shared.js` 的 `videoMap`，有用例）：
  - **逐点拉伸**（缺省）：两个锚点之间按直线插值，锚点上严格对齐；两头按 60 帧一秒往外推。适合"放视频看对应到轴的哪儿"。
  - **只按第一个点**：处处 60 帧一秒，仿真和视频的快慢差会随时间累积，看得出哪段仿真快、哪段慢。
- **联动**：
  - 视频在放时，时间轴的光标每一帧跟着走（`requestVideoFrameCallback`），帧画面每 60 毫秒刷新；
  - 视频停着时，在时间轴上点、拖、步进，视频跳到对应的时刻；
  - 控制条的"播放"也改成控制视频。

**怎么用**：
1. 点"打开本地视频"选文件（只在你的浏览器里读，不上传）。
2. 取消"联动"。把视频停在某个动作刚出手的画面（"◀ 1/60""1/60 ▶"逐帧挪），时间轴用 ⏮ ⏭（步进单位"动作开始"）走到同一个动作，点"打点"。
3. 打两三个点（隔开一点，比如每轮第一个动作），打开"联动"，播放视频。
4. 锚点列表里每个点都写着"仿真比视频快 / 慢几秒"（按第一个点算，同 `pnpm trace`）。落在某一行开头的锚点可以"导出成场景的 video.marks"，贴进场景文件，`pnpm trace` 就能用。
5. 锚点按场景存在浏览器里，下次打开还在；场景里写了 `video.marks` 的，第一次打开时直接用它们当锚点。

**限制**：
- **B 站、YouTube 的网页嵌入不能联动**：B 站播放器没有给网页读进度、跳转的接口。YouTube 有接口（IFrame API），但精度只到约 0.1 秒、跳转慢，原型没接。所以要用本地视频文件（自己录的，或下载的教学视频）。场景里 `video.url` 是 mp4 / webm 直链的，会直接加载。
- 视频的帧率不一定是 60（30 帧的视频逐帧挪一下是 2 帧）。
- 锚点之间按直线拉伸，等于假设这一段里仿真和视频快慢均匀；中间差得多的地方要多打几个点。
- 没在真浏览器里测过：只有用例（换算）和在 Node 里模拟页面（打开视频、打点、导出、时间轴步进时视频跟着跳）。请你用一段真视频试一下。

**以后可以做**（看你试了以后的反馈）：
- 打点时自动吸附到最近的"动作开始"。
- 锚点一多，直接在时间轴上画"仿真比视频快慢"的曲线，一眼看出哪个动作的帧数可能不对（就是校准，engine-quality-plan P4）。
- 接 YouTube（精度够看个大概）。

## 4. 视图 F：对视频（2026-10-25，原型）

视图 E 保留原样（视频栏照旧）。录像为主的看法单独做成视图 F（`web/designs/f-video.html`）：
- 命令行：`pnpm timeline <场景> --view f`，写到 `out/<场景名>.f.html`；
- 网页：在"场景"页运行后切到"F 对视频"。

**布局**：
- 左边大块放视频：打开本地文件；场景的 `video.url` 是能直接放的媒体文件时直接用它，B 站网页不行。
- 视频下面一条整局的时间轴：
  - 谁在场；
  - 各人的动作（大招最深，技能、变奏、声骸次之，普攻最浅）；
  - 每秒伤害；
  - 锚点（菱形）。

  点一下或拖动，时间轴和视频都跳过去。
- 再下面是"此刻"：
  - 每人在做什么（动作第几帧）、能量 / 协奏 / 共鸣回路、还在冷却的技能；
  - 前台那个人身上的 buff 与加了什么；
  - 最近 1.5 秒的伤害。
- 右边是分段，每次上场一行：
  - 视频里的时刻、谁（变奏标出）、上场多久；
  - 这段全队的伤害与占比；
  - 仿真比视频快 / 慢多少（这段开头有锚点时）；
  - 打了什么（连着的同一个动作压成"×n"）。

  视频在放时当前段高亮并跟着滚，点一行跳过去。
- 锚点（视频这一刻 = 仿真这一帧）来自场景的 `video.marks`，也能在这里打点、导出。存在浏览器里，和视图 E 的分开存。

**操作**：
- 空格：播放 / 暂停（有视频时放视频，没有时按世界时间走）；
- `,` `.`：逐帧；
- ← →：前后 1 秒。

**照录像记的轴**：`scenarios/tys-video.yaml` 是第一份，桃渊散，你的录像 BV1o7kfBPE6y，怎么记的见 `docs/tys-confirm.md`。
- 这类场景写 `purpose: replay`（录像剖析）：目的是对着视频把这一局从数值上看懂，不是轴教学；敌人走位、出招不建模，DPS 只作参考，视图 F 顶上标"录像剖析 · DPS 仅供参考"，`pnpm sensitivity` 不跑它；
- 每次切人一段；每段末尾写 `at <世界秒>`，把下一次切人对到录像的时刻；段里读出来的 E / 大招 / 声骸也各用一个 `at` 钉到录像的时刻（2026-10-26 起）；
- `video.marks` 是各段切人那一行在视频里的时刻。视图 F 打开就有这 25 个锚点，选好本地视频就能一边放一边看。

**录像里看到的动作**（2026-10-26）：场景的 `video.events` 写录像里读出来的动作，一条一个字符串"<视频秒> <角色> <动作>"（如 `"15.0 散华 E"`）。动作照轴的写法，别名也行。
- 时间轴最上面一排小三角是这些动作，悬停看对得怎样；
- 分段里每段多一行"录像"：每个动作写出仿真里同一个人、同一个动作是早了还是晚了几秒（前后 5 秒内找最近的），仿真里没有的（如异构武装的声骸）标出来；
- 每段另一行写上场的人进场 → 离场时的能量、协奏。

`tys-video.yaml` 记了 50 个（E / 大招 / 声骸 / 变奏，2026-10-26 逐帧重记）。

**录像里敌人的血条**（2026-10-26）：场景的 `video.hp` 写录像里敌人血条的读数，一条"<视频秒> <剩余比例>"（如 `"55.25 0.998"`）。第一条是血条出现（开始打这个敌人）的时刻。
- 视图 F 在每秒伤害下面多一条"敌人生命"：点是录像的读数，线是仿真从第一条那一刻起的累计伤害（按敌人生命折成比例）。悬停点看两边各剩多少。
- 用处：仿真只有一个敌人。录像前面另有小怪、或者"打死"的时刻对不上时，拿血条比伤害，不拿打死的战斗秒比。
- 怎么读：血条红色部分占全长的比例（逐帧截图量像素，约 ±1%）。

**每段的 buff 与变奏**（2026-10-26）：分段里每段另有
- "写了变奏，仿真里 X 协奏 N 没满，按普通切人"：录像是变奏、仿真切出者协奏没满（`pnpm sim` 的"轴可能有问题"同一条）；
- "buff 覆盖"：这段前台那个人身上带伤害的计时 buff 各盖住这段的多少（常驻的不列）；
- 有大招的段：大招伤害最大的那一下吃到了哪些计时 buff（如渊武 6 链、深塔的变奏暴伤）。

**还没做的**：
- 普攻、重击那一级的录像动作（4 帧一秒的截图认不出普攻打了几段）。

**检查**：
- Playwright 截图：桌面 1600 宽与手机 420 宽；
- 视频用转成 VP9 的 70 秒片段。无头 Chromium 不带 H.264 解码，平常浏览器能直接放原视频。
