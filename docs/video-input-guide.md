# 攻略视频与文字轴：怎么准备、怎么用（2026-10-25）

加新队伍或新轴时，你提供视频和文字轴，我写成场景并拿视频核对时间。这份写清：什么样的材料最有用、文字轴该怎么写、给 Gemini 的提示词。

前两批（景尤守 4 条、爱弥斯队 2 条）的经验见 `docs/jys-videos.md`、`docs/alm-confirm.md` §3。

## 1. 什么材料有用

| 材料 | 能拿来做什么 | 例子 |
|---|---|---|
| **不剪辑的连续实战，画面带计时器**（矩阵 / 深塔倒计时） | 一轮多长、每一段多长（计时器在大招、变奏动画里停，和仿真的"战斗秒"同口径；视频时间对应"世界秒"）；找出仿真哪段慢 | 5R18Z（BV1uXYT6dEiQ）后半段：量出一轮 25.8 战斗秒，带出了"守岸人大招 178 帧能切人""切人冷却每人单独计"等改动 |
| **作者自己画的流程图 / 图标轴** | 轴的权威版本，纠正二手整理的错误 | 爱琳莫、爱琳守（长风ei）、景燃全局（金铃子）结尾的图 |
| 解说里讲到的机制、取消手法 | 关掉待确认的问题、补对照场景 | "强化重击键亮起比第 4 段伤害早""a4 闪避打断" |
| 讲解时的慢放、剪辑片段 | 作用小：量不了时间 | 爱琳守、爱琳莫的讲解部分 |
| 别人的伤害数字 | 几乎没用：配装不同 | —— |

**最有价值的是你自己账号的录像**：配装与场景完全一致，可以同时校准时间和伤害（跳字填进 `docs/calibration/points.yaml`）。录法：

- 60 帧原画，不剪辑，开着界面（计时器、跳字、角色头像都要在）；
- 最好开按键显示叠加层（如 NohBoard），能看到每一下按在什么时候。像"连续切人最短隔多久""闪避取消在第几帧"这类问题能直接回答；
- 一条视频只打一种轴，从开场打满 3 轮以上；
- 文件名写清队伍、轴名、日期。

**找别人的视频时**，优先挑这三样里占两样的：一整局不剪辑的实战、画面带计时器、作者附了流程图。B 站简介和置顶评论里常有作者的文字轴和配装，顺手存下来（贴进文字轴文件的开头）。

## 2. 文字轴写成什么样

上两批 Gemini 整理的文字轴出过这些问题：

1. **二手转述与作者原图不一致**：
   - "2A-E"写成"a2 + a3 + E"；
   - 爱琳守多写了一个声骸；
   - 处决的位置写错；
   - 第一项误标成"维e"。
2. **记号有歧义**："3A"是 A1–A3 还是接在别的动作后的三下；"Z"是点按还是按住；"处决"是必放还是"有就放"；括号里的步骤是可选还是限定链数。
3. **没有时间戳**，没法对回视频。
4. 作者原话、整理者的理解、技巧说明混在一起。
5. 缺作者的链数、武器、共鸣效率，以及一轮的边界在哪。
6. 本地文件链接写的是另一台机器的路径。

所以文字轴请按 §3 提示词的格式产出，要点是：

- **先照抄作者的图**；
- **每一步带时间戳和出处**；
- 普攻写到第几段；
- 不确定的地方标出来，不要补全。

文件放在 `~/wuthering-waves/`，文件名带 BV 号。

## 3. 给 Gemini 的提示词

```text
你是《鸣潮》战斗录像的转录员。请分析这个视频，产出一份给 DPS 仿真程序用的结构化记录。
原则：只记录视频里能看到 / 听到的东西；凡是推断都标【推断】，看不清的标【不确定】，不要补全或"合理化"。
时间一律写视频时间 mm:ss（能精确到 0.1 秒的写 mm:ss.s）。

## 1. 基本信息
- 标题、BV 号、作者
- 队伍三人；画面或解说里出现的链数、武器（及精炼阶）、声骸套装、首位声骸、共鸣效率要求（标出出处时间戳）
- 视频结构：哪些时间段是讲解 / 慢放 / 剪辑，哪些是不剪辑的连续实战（给起止时间戳）

## 2. 作者的流程图 / 轴图（最重要）
- 列出画面里所有流程图、图标轴、文字轴出现的时间戳
- 逐格照抄图上的内容，保持原有的记号和顺序（例如"Q-2A""处决-R""3A-强化E"），按角色分行，标出"变奏""切人"箭头的位置和图上的编号
- 图上写的说明（切人次数、难度、共鸣效率等）照抄
- 括号、颜色、虚线等特殊标记照实描述，不要解释

## 3. 逐步操作（启动轴、循环轴分开）
每一步一行，格式：
| 序号 | 视频时间 | 角色 | 操作 | 出处 | 备注 |
- 操作用以下记号，并写清第几段：A1/A2/A3/A4（普攻第几段，不要写"3A"）、Z（重击，注明点按还是按住）、E、Q、R、闪避、跳跃、处决、切人(→谁)、变奏(→谁)
- 一段普攻被什么取消（闪避 / 处决 / 跳跃 / 技能），写在备注里
- 出处写"流程图" / "字幕原文：……" / "解说原话：……" / "画面"
- 和流程图不一致的地方单独列出

## 4. 时间锚点（只记不剪辑的连续实战段）
如果画面上方有战斗计时器（矩阵 / 深塔倒计时），记录每个大招全屏动画开始前最后一帧的计时器读数和视频时间，例如：
| 视频时间 | 计时器读数 | 事件（谁的大招 / 变奏动画） |
至少覆盖连续 3 轮。读不清的标【不确定】，不要估算。

## 5. 解说里的技巧与机制说法
逐条照抄原话（带时间戳），例如"强化重击键亮起比第 4 段伤害早""声骸是脱手的"。不要改写成自己的话。

## 6. 你不确定或可能出错的地方
单独列一节。
```

**模型选择**：对结果影响最大的是能否准确读小字（流程图、计时器）、能否逐帧对时间。拿不准用哪个模型时，同一个视频让两个模型各跑一遍，随手挑几个时间戳回视频核对，用标得准的那个。不管用哪个，计时器读数和流程图我都会自己截帧复核，所以时间戳比文字本身更重要。

## 4. 我这边怎么用（给以后的会话）

- 视频放在 `~/wuthering-waves/downloads/`；截帧用草稿目录里的 ffmpeg（`pip install imageio-ffmpeg` 装进一个 venv，用它带的可执行文件）。
- 先截流程图（多在视频结尾或"流程轴"段）按原分辨率读，**按图写场景**，和文字轴的差异记进该队的 confirm 文档。
- 连续实战段按每秒 1 帧截总览，找每轮都有的全屏动画当锚点（大招、守岸人的洞悉…），再在锚点附近按每秒 6–10 帧截，读动画前最后一帧的计时器；一轮时长取 3 轮平均。
- 对出差距后按段拆开（`pnpm trace --loop k` 对视频的锚点），找是哪种规则 / 数据让仿真慢或快；能改的改，改不了的写对照场景（只差一处）量影响。
