# Antigravity 与 Codex：共识

比较对象为 2026-11-08 的两份总体评审：[Antigravity](../overall-review-antigravity-20261108.md)（v2，全仓深潜后更新）、[Codex](../overall-review-codex-20261108.md)（同日独立复核更新版）。只依据这两份文本，没有复查其引用的代码、资料或实验。文中的代码现状、数字与复现结果都是转述，裁判没有核验。

这里的"共识"指双方都明确表达了相同的方向或判断。同一议题可能原则上一致，但在定性或做法上不同，这部分见 [dispute.md](dispute.md)。只有一方展开的观点见 [blindspot.md](blindspot.md)，不把另一方的沉默当成赞同或反对。

## C01. 对用户诉求的理解：底座与应用互相牵扯，数据不可靠、差异难收敛

- **Antigravity**：用户有两个核心纠结。一是"底座与应用的拉扯"：想专心做底座，验证底座又离不开具体场景和应用。二是"数据不可靠与差异不收敛"：上游是社区表格、解包和社区站，对不上时缺乏能快速收敛的机制。来源：[§1.1](../overall-review-antigravity-20261108.md)。
- **Codex**：用户澄清底座是重点，应用提供验证场景；希望像编译器一样，把轴与配置转换成有时间顺序的事件和状态。困难是第三方或解包数据并非绝对可信，数值不符时又缺少成熟的定位和收敛机制。来源：[§1](../overall-review-codex-20261108.md)。

两份对问题的复述基本相同。Codex 另外记下了讨论的演进：首个应用一度先选"读懂教学轴"，之后改为底座优先（见 [B-X27](blindspot.md)）。

## C02. 逐帧仿真引擎是底座，教学轴、录像剖析、配装分析与 AI agent 都是上层使用者

- **Antigravity**：把底座定位为"编译器 + 确定性状态机"；教学轴分析、深塔 / 矩阵 / 全息视频剖析、配装择优、AI agent 定量推理都是上层应用，与现有 `src/engine/` 的纯函数设计契合。来源：[§0 第 1 项、§3 图、§6](../overall-review-antigravity-20261108.md)。
- **Codex**：以可复用、可查询、可诊断的逐帧仿真底座为建设重点；把编译器的类比延伸为"编译器 + 执行器 + 调试器"，应用和 agent 读取同一份结构化结果。来源：[§1、§3.1、§9.1](../overall-review-codex-20261108.md)。

双方一致的是分层方向。底座的边界和建设顺序有分歧，见 [D01](dispute.md)、[D12](dispute.md)。Codex 另外按用户的选择把教学轴定为优先验证的应用，Antigravity 没有排定先用哪个应用验证。

## C03. 现有内核是可保留的基础，不需要推倒重写

- **Antigravity**：认为"内核骨架极其优秀"，列出必须保留的基石：纯函数三层与 `vars` 显式状态、七相位 tick 与三时钟、经 golden 验证的公式层、`checkTick` / `checkLog` 不变量、nanoka / WuwaLAB 三方交叉核对。来源：[§0 第 2 项、§2.1](../overall-review-antigravity-20261108.md)。
- **Codex**：纯库边界、固定步长、多时钟、独立判定、显式钩子状态、假设开关、公式对拍、不变量、fuzz、场景回归与 conformance 都可以继续用；要补的是这些能力之间的契约、身份和证据连接，"并非另造一套执行底座"；也不要求改成事件驱动内核、全程不可变状态、自创机制语言，或立即迁移 Rust。来源：[§4 开头、§10、§13.1](../overall-review-codex-20261108.md)。

双方的改进建议都建在现有执行器上。Antigravity 的"双模"是在同一个确定性内核之上多加一种运行模式（§3），同样不是重写内核。Codex 认不认同加这种模式，文本没有表态（见 [D02](dispute.md)）。

## C04. "可靠"是指在写明的前提下结果确定，而不是机制都已经实测过；输出要带上所依赖的前提

- **Antigravity**：可靠等于"确定性 + 前提透明"。每次输出附带本次碰到的规则快照（`Summary.assumptions`），回答永远是"在某些开关取某值的前提下，第 720 帧的状态严格是 X"这样的逻辑命题。来源：[§4.2](../overall-review-antigravity-20261108.md)。
- **Codex**：确定性（同样输入得到同样结果）与符合游戏（模型能否解释或预测游戏现象）要分别建立；给结果附上适用范围和有关假设；运行记录要关联实际用到的规则开关等运行身份。来源：[§2、§2.2、§5.3](../overall-review-codex-20261108.md)。

## C05. 数值与机制规则分开处理；规则还没定的读法，做成离散、可切换的候选

- **Antigravity**：静态数值（倍率、能量、协奏、动作帧……）与交互规则（切人冷却、大招时停里顿帧走不走、召唤物算不算角色、切人保不保留回路）分成两类；凡是有两种读法的规则，一律在 `assumptions.ts` 里做成开关。来源：[§4.1](../overall-review-antigravity-20261108.md)。
- **Codex**：区分数值参数与机制结构。"命中加多少"可以在有依据的范围里扫描，"起手给还是命中给"适合列成离散候选。每个选定的候选下仍做确定性仿真，在外层分别跑各候选再比较，不在单次运行里随机猜规则。来源：[§6.2、§6.3](../overall-review-codex-20261108.md)。

两边划的界线不完全一样：Antigravity 把动作帧数归入数值，Codex 则强调资源数量有出处时，到账时机仍要单独标出处。数值能不能免测，见 [D04](dispute.md)。

## C06. 实测按影响排序，不必、也不应全量实测

- **Antigravity**：靠人工把所有角色、所有动作逐一实测会拖垮项目；先看敏感度矩阵，只把会导致断轴或结论反转的假设送去实测。来源：[§4 开头、§4.2、§7 P1 第 2 项](../overall-review-antigravity-20261108.md)。
- **Codex**：先检查比较工具和执行实现里能独立验证的部分，再把剩下的疑问交给游戏实验，减少无效实测；候选会改变关键门槛的才优先设计区分实验，影响小的按 T16 登记、延后实测。来源：[§2.2、§6.3](../overall-review-codex-20261108.md)。

阈值，以及能不能说"永不实测"，有分歧，见 [D09](dispute.md)。

## C07. 整局录像的总量贴合会掩盖互相抵消的错误，贴合度要分项看

- **Antigravity**：引 replay-retro："心的直接伤害偏低 8%、踏月归心偏高 2 倍，两者互相抵消，所以中 4 血条才差 2.4%"；`fit.ts` 的单一标量分数让这种抵消得以发生。来源：[§1.2 第 2 点、§2.2 症结五](../overall-review-antigravity-20261108.md)。
- **Codex**：差异收敛要"分开残差……不让总分隐藏互相抵消的错误"；引的是同一条复盘记录（心的部分伤害偏低、踏月归心偏高，累计血条仍然接近）；"一局总伤害贴合"推不出全部机制都验证过；`Fit` 已有的分项信息应继续使用，不能用一项变好去抵消关键规则的反证。来源：[§4 R03/R06 一节、§7 第 3 步与末段、§8 表](../overall-review-codex-20261108.md)。

总分在候选排序里还有没有用，见 [D10](dispute.md)。

## C08. 录像里的输入差异与测量噪声，要和引擎的规则误差分开

- **Antigravity**：玩家临场多走一步、Boss 后退导致晚 3 帧命中、空挥一下普攻，是"输入剧本的噪音"，不是底座的 Bug；不剥离开，就会在底座调参里陷入死循环。来源：[§1.2 第 3 点](../overall-review-antigravity-20261108.md)。
- **Codex**：把"本次分析是否适用"单列为一个问题（场景和录像用的武器、初态或环境不同时，要修输入或说明适用范围）；录像时间是需要映射的外部坐标；资源环是近似读数，累计血条会受实际暴击序列影响。来源：[§2.1、§3.4、§7 末段](../overall-review-codex-20261108.md)。

## C09. 强制指定的状态不是引擎推出来的结果，要和规则推演区分开，并留下记录

- **Antigravity**：`能量满`、`敌人 失谐`、`敌人 换` 是"上帝视角指令""状态补丁"，不是玩家的按键；锚定模式在补齐状态时输出 `syncResidual`，记下补了多少。来源：[§2.2 症结一第 5 点、§3.2](../overall-review-antigravity-20261108.md)。
- **Codex**：`at` 对时、能量满、指定失谐属于用户或录像给定的输入条件，应说明它们限制了哪些预测；用这些条件复现后续过程有价值，但不能再拿同一个被指定的量去证明模型能自己预测对。来源：[§3.3、§7 倒数第二段](../overall-review-codex-20261108.md)。

双方一致的是"要区分"。这些指令该不该留在排轴语法里、补位算不算正当的调度策略，见 [D02](dispute.md)。

## C10. 定位机制要靠小范围、受控、能区分候选的实验，而不是在整局录像里多变量盲猜

- **Antigravity**：停止在深塔整局录像里盲猜多变量组合，改用木桩上的单变量实验来结案；四级漏斗的每一级都是隔离条件的实验。来源：[§5、§7 P1](../overall-review-antigravity-20261108.md)。
- **Codex**：有价值的观察要能区分候选，例如读命中前的资源，而不是技能结束时的值；实验要控制初始值、避免被上限截断、排除其他回资源的效果；受控短实验能支持特定条件下的时机、资源和数值。来源：[§6.1、§6.2、§8 表](../overall-review-codex-20261108.md)。

"单变量"要不要扩展到交互组合，见 [D07](dispute.md)。

## C11. 先修好比较与校准工具本身，再靠它们下结论（双方都列为 P0）

- **Antigravity**：P0 是"修掉校准工具本身的口径 Bug 与混杂评分（立竿见影）"，即 calibration 的 loop 时钟和 fit 的评分拆分。来源：[§7 P0](../overall-review-antigravity-20261108.md)。
- **Codex**：P0 是"量尺与结果状态明确"：校准时钟、实例身份、目标的统计边界、完成范围、缺失的观测（R01、R03、R09–R11）；"先保证现有工具不会……给出误导结论，再扩展完整状态查询"。来源：[§9.2](../overall-review-codex-20261108.md)。

两边的 P0 都包含校准 loop 时钟和 fit 的问题，但在 fit 上各自指出的缺陷不同。Antigravity 指的是量纲混杂、漏了跳字、两类改动混在一个榜单里；Codex 指的是匹配不是一对一、锚点全部失配时得 0 分。P0 的其余内容也不一样，见 [D12](dispute.md) 和 [blindspot.md](blindspot.md)。

## C12. 校准点 `loop` 的时钟口径前后冲突，需要明确是世界秒还是战斗秒

- **Antigravity**：`calibration.schema.ts` 的注释和 `points.yaml` 的说明都写世界秒，`calibration.ts` 的 `simValue` 却返回 `span.endT - span.t`，也就是战斗秒。来源：[§2.2 症结四](../overall-review-antigravity-20261108.md)。
- **Codex**：schema 里 loop 的注释和校准说明写世界秒，`simValue` 返回 `endT - t`，而按 `EventBase` 的定义 `t` 是战斗秒；最小复现输出 `[6]`（对应 10 世界秒、6 战斗秒的人造日志）。来源：[§4 R01](../overall-review-codex-20261108.md)。

双方都接受"显式区分两种时钟"的做法。Antigravity 写的是"或者显式区分 `loopWorld` 与 `loopBattle`"，Codex 写的是"在观测中明确时钟"。这到底是代码 bug 还是文档契约冲突、该不该直接改算法，见 [D03](dispute.md)。

## C13. 事件的直接来源应在运行时记下来，不能靠事后的 `walkOwners` 按邻近关系去推

- **Antigravity**：`walkOwners` 对日志做单遍线性扫描，用最近的 anchor 覆盖归属；同一帧多个 buff 到期时会张冠李戴。应该在事件推入日志时就写上触发源（`SimEvent.causedBy`）。来源：[§2.2 症结二、§6 第 1 项、§7 P2 第 1 项](../overall-review-antigravity-20261108.md)。
- **Codex**：`walkOwners` 的注释已经写明，同一帧多个 buff 到期时，后续事件可能都归到最后一个 buff 头上。应让资源变化、判定生成、buff 施加与到期都带上直接原因的引用；列为 P1，验收标准是"同帧两个到期效果不串来源"。来源：[§4 R02、§9.2 P1](../overall-review-codex-20261108.md)。

Codex 另外补充了"归属推错不等于结算数值也错"、诊断不能改变执行等约束；Antigravity 另外补充了 BFS 队列交错这条错归路径，以及运行时现成的 `bus.chain`。见 [B-A03](blindspot.md)、[B-X07](blindspot.md)、[B-X14](blindspot.md)。

## C14. 底座要提供按时刻查询状态的接口（`inspectStateAt` / `stateAt`）

- **Antigravity**：现在没有标准的 `inspectStateAt(frame)`，上层要从多个局部数组里自己拼。应该一次给出这一刻的状态切片：场上动作与局部帧、三人的资源、生效的 buff 与剩余时间、敌人的异常层数、实时合成的面板。来源：[§2.2 症结三、§6 第 2 项、§7 P2 第 2 项](../overall-review-antigravity-20261108.md)。
- **Codex**：输出只有展示用的轨道，没有统一的完整状态查询与恢复契约。建议 `stateAt` 返回某个明确边界上的结构化状态，查询本身不推进时间、也不触发效果。来源：[§3.2、§4 R04、§9.1](../overall-review-codex-20261108.md)。

怎么建、建在什么基础上，有分歧，见 [D11](dispute.md)。

## C15. 等待和阻塞的原因要能查，并说明是哪一类原因

- **Antigravity**：`explainWait(res, cmdIndex)` 以调度器的 `WaitEvent` 为基础，按帧拆出阻塞链，例如前 13 帧是 `settled` 在等上一招出手、后 32 帧是 `resource` 在等能量。来源：[§6 第 3 项](../overall-review-antigravity-20261108.md)。
- **Codex**：记下"等待 5 帧"时，要说明是游戏限制、调度策略还是给定条件里的哪一类，否则判断不了这段等待是否必要；`whyNot` 做只读的动作条件检查，说明查过哪些阻挡项。来源：[§3.3、§9.1](../overall-review-codex-20261108.md)。

两边侧重不同：Antigravity 要的是对一段已经发生的等待逐段拆解；Codex 还要求说清楚返回的是首个阻挡，还是查过的全部阻挡（见 [B-X04](blindspot.md)）。

## C16. 底座对外不应只给事件流水账和一份总汇总，而要提供结构化的查询原语

- **Antigravity**：底座向上暴露的不应仅仅是一份 `SimEvent[]` 和一个总 `Summary`，而要收敛成四个标准化的查询与诊断原语。来源：[§6](../overall-review-antigravity-20261108.md)。
- **Codex**：列出 `compile`、`run`、`stateAt`、`eventsBetween`、`explainEvent`、`whyNot`、`diffRuns`、`compareObservations` 等建议能力，先做成纯库与 CLI JSON，应用和 agent 读同一份结构化结果。来源：[§9.1](../overall-review-codex-20261108.md)。

两份清单只在状态查询、阻塞解释、事件来源三处能对上，其余都是各自独有，见 [B-A08](blindspot.md)、[B-X24](blindspot.md)。

## C17. 教学轴分析的价值在于把断轴、等待和容错暴露出来，不能把问题凑掉

- **Antigravity**：自由推演模式下，差 1.1 点协奏导致变奏失败、差 18 点能量开不出大招，都应当直接报错或暴露等待时间，"这正是教学轴分析最核心的价值"；严格暴露卡帧、缺能、断轴，不靠假补位硬凑。来源：[§3 图、§3.1](../overall-review-antigravity-20261108.md)。
- **Codex**：容错要显示在测过的延迟范围内，最先损失的是哪项资源、命中、buff 或后续窗口，不能只看 DPS 有没有变；协奏不够时调度器会改成普通切入，并报告 `introMissed`。来源：[§3.3、§8](../overall-review-codex-20261108.md)。

## C18. 不变量、golden 这类程序检查是有价值的回归护栏

- **Antigravity**：不变量检查"是底座最宝贵的防回归护城河"；公式层经过 golden 扰动验证。来源：[§2.1 第 3、4 项](../overall-review-antigravity-20261108.md)。
- **Codex**：单元测试、不变量、golden 和 conformance 都有价值，可以继续用。来源：[§2.1、§4 开头](../overall-review-codex-20261108.md)。

这些检查能证明多少，特别是能不能代表游戏事实，有分歧，见 [D04](dispute.md)、[D05](dispute.md)。
