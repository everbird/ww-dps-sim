> **状态**：v0.2（2026-10-12）：时间轴的四种视图 A–D（§2.1）与 `pnpm timeline --view`；v0.1（2026-10-05）随实现写成（`web/app/`，用例 `tests/web.test.ts`）。技术栈按总设计第 10 节的倾向定为 Vite + Svelte 5（2026-10-05 用户确认）。

## 0. 要点

1. **只在本机用**：生成数据（`data/generated`）不进 git、不发布，网页直接读仓库里的文件。`pnpm web` 起开发服务器（`http://localhost:5317/`）；`pnpm web:build` 打包到 `out/web/`（含数据，不要发布）。
2. **五页**：场景（编辑、运行，看时间轴页面，可切换原版与视图 A–D）、对比、副词条边际、声骸择优、视图说明；结果与 `pnpm sim` / `timeline` / `compare` / `marginal` / `optimize` 相同（同一套引擎与分析函数）。
3. **引擎在 Web Worker 里跑**：择优要十几秒，页面不卡。
4. **改动存在浏览器**：场景与库存的编辑存在 localStorage，不写回仓库；要留下就"下载"后放回 `scenarios/`、`inventory/`。
5. **时间轴有五种看法，都保留**（v0.2，用户 2026-10-12 定）：原版（含调试表）与视图 A–D 关注点不同，按需切换；网页与 `pnpm timeline --view` 用同一份模板与数据，同样输入得到逐字节相同的输出。
6. **用域名访问**：Vite 只认 localhost，用域名打开时把域名写进环境变量 `WEB_HOSTS`（逗号分隔），如 `WEB_HOSTS=example.com pnpm web --port 8014 --host 0.0.0.0`；不写死在仓库里。

## 1. 结构

| 文件 | 内容 |
|---|---|
| `web/app/vite.config.ts` | root 是 `web/app`；`server.fs.allow` 放开仓库根目录（读 `data/`、`scenarios/`、`inventory/`） |
| `src/gamedata.ts` | 浏览器侧装配 `GameData`：同 `src/data/load.ts`，文件由 `import.meta.glob` 读（动作文件只读用得到的块），交给同一个 `buildGameData` |
| `src/handlers.ts` | Worker 的各请求：`info`、`run`（仿真 + 时间轴页面 HTML）、`compare`、`marginal`、`optimize`；场景 / 库存的 YAML 用同一套 zod schema 校验，报错带文件名与位置 |
| `src/worker.ts`、`src/api.ts`、`src/protocol.ts` | 消息收发（按 id 配对）与请求 / 回复的类型 |
| `src/docs.svelte.ts`、`src/Editor.svelte` | 可编辑的 YAML：仓库里的场景与库存（构建时读入）、网页里另存的副本；改过的与副本存 localStorage |
| `src/views/*.svelte` | 五页 |
| `src/designs.ts` | 视图 A–D 的理念与优劣（"视图说明"页） |
| `web/designs/` | 视图 A–D 的模板（各自是完整网页）与共用的 `shared.js`；`renderDesign` 把 `shared.js` 与数据内联进去 |

时间轴页面的数据模型移到 `src/report/timeline.ts`（纯函数），CLI 与网页共用；"场景"页把它嵌进 iframe（`srcdoc`），高度跟着内容。

### 2.1 时间轴的视图 A–D（v0.2）

原版的问题（2026-10-12 截图看到的）：buff 34 行、每行 13 像素，标签挤在一起被截断；动作名放不下就截掉；"等待"一行几乎一整条（派生窗口、优先级这类正常节奏也画了）；能量协奏太矮、没有刻度。四种视图各从一个角度解决：

| 视图 | 一句话 | 适合 |
|---|---|---|
| A 精修泳道（`a-lanes.html`） | 结构同原版；动作名放不下挪到条下方的标签行；只画"卡住的等待"（不含派生窗口、优先级、连段、同一 tick、写轴要求的）；buff 按受益人分组、缺省只列影响伤害的，标签栏写全名与稳态覆盖率 | 想要原版但更好读 |
| B 角色分卷（`b-volumes.html`） | 每个角色一卷：动作、每段伤害（线性柱高）、能量协奏、身上的 buff；buff 用"给的人"的颜色；共用吸顶时间轴，可以放大到某一段上场 | 研究一个角色的伤害构成与 buff 覆盖 |
| C 指令表格（`c-ledger.html`） | 一行一条指令：开始、到下一条、伤害、之前卡在什么（卡住的高亮，正常节奏淡化），最后一列是本轮甘特条，等待画成斜纹 | 对轴、对视频、调排轴 |
| D 概览与透镜（`d-lens.html`） | 顶部全程导航（每秒伤害堆叠柱，拖动选范围，斜线连到下方放大的那段，和下方不对齐）；主图里另有一条对齐的每秒伤害；右侧步进区与检查器 | 看单个瞬间的伤害构成、逐段过轴 |

D 的步进区与检查器：

- **步进**：◀ ▶ 或键盘 ← →，单位可选命中、动作开始、切人、战斗秒、一帧；Shift + ← → 按 1 战斗秒，`,` `.` 按 1 帧，Esc 解锁。步进时自动锁定光标，走出范围时视窗跟着平移。
- **上一个 / 当前 / 下一个**：三行并排写出各是什么（如"当前命中 第 177 / 455 个：椿 盛绽·A2-2，期望 6,288"）、相差几秒，上下两行点了也能跳；主图上标出当前步（命中画圈、动作描边、切人画三角）。
- **检查器**：那一刻每个人的动作、能量协奏、身上的 buff；敌人的偏谐值与白条（当前 / 上限）和状态（失谐、瘫痪）；最近一段伤害的乘区拆分与生效的加成。
- **buff 折叠**：每人收成一行合计（按乘区 + 条件合计，取最大的三项），鼠标悬停浮出清单，点一下钉住就地展开（触摸屏只用点）。
- **说明收进 ⓘ**：键盘操作、导航的含义、敌人量表的含义；悬停显示，点一下钉住。

展示用的归类规则（写在 `web/designs/shared.js`，不影响仿真）：等待里派生窗口、优先级、连段、同一 tick、写轴要求的算"正常节奏"（`RHYTHM`）；在任何一段命中的生效 buff 里出现过的算"影响伤害"；每秒伤害按世界秒分桶；乘区的中文名 `ZONE_NAME`。

时间轴模型（`src/report/timeline.ts` 的 `timelineModel`）为此新增两项：`buffOwners`（buff → 登记它的角色，声骸、武器、套装算穿戴者，场景 buff 记 `env`）与 `buffInfo`（buff → 乘区、每层的值（已按谐振阶取好）、层数上限、原文、过滤条件）。

命令行：`pnpm timeline <场景> --view a|b|c|d` 写 `out/<场景名>.<视图>.html`（`TIMELINE_VIEWS`、`renderDesign`），与网页里的同一份模板与数据；不写 `--view` 是原版。
