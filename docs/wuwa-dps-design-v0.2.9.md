## 0. 一句话定位

一个**把时间轴作为一等公民**的鸣潮期望 DPS 计算 / 配装择优工具。

与现有工具（GitHub 上多为静态乘区计算器）的根本区别：现有工具是"用户手动勾选所有增益 → 算一发静态伤害"，
无法表达 buff 生效窗口、合轴、后摇并行、能量循环随时间的演化。本工具通过**逐帧仿真**让这些自然涌现，
因此在"给定轴下取舍声骇/配装"时更准确。

### 0.1 项目永久前提（不随版本变化的决策）

- **一切满级恒定**：角色90级、技能满级、武器满级。技能倍率是常量，**永不做逐级可调**。
  理由：只有满级毕业玩家才需要合轴/配装择优这种精细优化。→ 无成长曲线插值、无等级参数、面板取满级档。
- **帧率 60fps**，时间轴最小单位 = 1 帧。
- **单队三角色**为基本作战单元。
- 数据与逻辑分离：版本更新只改数据文件，不动引擎。

## 1. 三层状态模型总览

```
BattleState（全局战场状态）
├── time                       全局帧（60fps，最小时间单位=1帧）
├── enemy                      敌人状态（防御/抗性 + 三套敌人槽：白条削韧、韧性、偏谐值累积）
├── switchCooldownRemaining    全局切人CD（1秒=60帧内禁止再切）
├── lingeringEffects[]         持续效果池（领域/图腾/落地的outro team buff，生命周期独立于角色在场与否）
├── activeBuffs[]              当前生效buff（含层数、剩余时间）
└── characters: { charA, charB, charC }   三名角色，各自独立
        每个角色 = CharacterRuntimeState:
        ├── status              onfield_active / backstage（后台）
        ├── actionPointer       当前动作 + elapsedFrames（后台也持续推进！）
        ├── concerto            协奏值（个体，上限100）
        ├── resonanceEnergy     共鸣解放能量（个体）
        ├── resonanceEfficiency 共鸣效率（影响回能，仅作用于大招能量）
        ├── tunabilityEff       偏谐效率（影响偏谐累积）+ 谐破增幅（影响谐度破坏伤害）
        ├── coreResource[1..3]  核心资源槽（角色专属，语义各异：黯核/层数/形态等，见4C）
        └── cooldowns           各技能CD

  enemy = EnemyState:
    ├── def / resistance[8系]
    ├── 白条 + toughnessAccum          （削韧槽，破盾回能）
    ├── 韧性 + poiseAccum              （韧性槽，硬直/打断相关）
    ├── 偏谐阈值 + tunabilityAccum      （偏谐槽，满则失谐，见4B）
    ├── isDisharmony / tunabilityLockUntil
    └── shiftState / interferenceState （偏移/干涉 debuff，见4B.3）
```

**核心不变量（贯穿全文的三条铁律）：**

1. **一切伤害与资源，绑定"角色自己的动作进度指针跨过某个判定帧"这一事件，与谁是当前操作角色无关。**
   → 后台角色的后摇照常走帧、照常出伤害、照常回能。
2. **tick 是全局的，不是单角色的。** 每帧推进时，同时推进全部三名角色的动作指针，谁的指针跨过判定帧，谁就触发结算。
3. **切人随时可切（受1秒CD门控），切走不打断被切角色的后摇**，后摇转入后台继续走完。这是"合轴"的机制根源。

## 2. 全局 tick 仿真循环（计算引擎核心）

这是整个工具的心脏。轴验证与轴搜索复用同一套循环，区别只在遍历策略。

```
for each frame t in [0 .. rotationTimeBudget]:

  # ---- A. 推进所有角色动作指针，扫描hit ----
  for c in [charA, charB, charC]:            # 前台后台一视同仁
      推进 c.actionPointer（按时间膨胀规则，见下方注）
      for hit in c.currentAction.hits:
          if 指针本tick跨过 hit.judgeFrame（=xlsx「发生帧」）:
              # --- 伤害结算（见第3章9乘区）---
              dmg = evaluateDamage(hit, 当前生效buff按乘区汇总, enemy)
              accumulatedDamage += dmg
              enemy.toughnessAccum  += hit.削韧值                        # 削韧累积（→白条）
              enemy.tunabilityAccum += hit.偏谐值 × dealer.偏谐效率      # 偏谐累积（→失谐），见第4B章
              # --- 大招能量结算：on-hit，全队分配（见第4章）---
              distributeEnergy(hit.energyBase, dealer=c, others=其余两人)
              # --- 偏谐：失谐态下命中触发谐度破坏（见第4B章）---
              if enemy.isDisharmony:
                  accumulatedDamage += harmonyBreakDamage(hit, dealer=c, enemy)
                  enemy.tunabilityAccum = 0
                  enemy.tunabilityLockUntil = t + 谐破后锁定帧
                  enemy.isDisharmony = False

  # ---- B. 协奏能量：on-cast，只给施放者 ----
  for c in [三角色]:
      if c 本tick有技能「释放第一帧」:
          c.concerto = min(100, c.concerto + action.concertoGain)   # 数据源：图3能量论

  # ---- C. 破盾回能 ----
  if enemy.toughnessAccum >= enemy.白条 and 未破盾:
      for c in [三角色]: c.resonanceEnergy += 3     # 仅cost4/3 boss有白条
      标记已破盾

  # ---- C2. 偏谐值满 → 失谐 ----
  if enemy.tunabilityAccum >= enemy.偏谐阈值 and t >= enemy.tunabilityLockUntil:
      enemy.isDisharmony = True     # 强敌可能需专门「谐度破坏技」才结算，见第4B章

  # ---- D. 推进战场状态 ----
  推进所有 activeBuffs 计时/衰减；检查各buff的onSwitchOut是否本tick触发
  推进 lingeringEffects 池
  switchCooldownRemaining = max(0, switchCooldownRemaining - 1)

  # ---- E. 决策点：是否执行一个「动作指令」----
  # 轴验证模式：读用户给定序列的下一条指令
  # 轴搜索模式：枚举所有合法转移，交给搜索策略
  if 存在待执行指令 and 指令合法（见第5章边的合法性）:
      applyAction(指令)   # 可能是：接技能 / 切人 / 大招打断 / 声骇技能打断

最终 DPS = accumulatedDamage / rotationTimeBudget（秒）
```

**时间膨胀（顿帧）建模——之前标"需实测"，新版数据已给全**：
xlsx 新增列 `时间膨胀类型`（攻击顿帧/时停/全局时停/极限闪避顿帧/弹反顿帧）、`自膨胀系数`（0.01~0.8）、
`膨胀发生`，精确描述了顿帧如何拉伸时间轴。推进 actionPointer 时据此处理：
- **攻击顿帧**（最常见）：命中瞬间自身与敌人短暂定格，按 `自膨胀系数` 拉伸该动作耗时。
- **时停/全局时停**：影响范围不同（自身 vs 全局），全局时停会同时冻结三名角色的指针推进。
- 这直接影响合轴时"实际经过的墙钟时间"，进而影响 DPS 分母。v0 至少要处理攻击顿帧对轴总时长的贡献，
  否则轴时间会算短、DPS 偏高。具体膨胀公式建议用白芷案例对着 xlsx 的系数实测校准。

## 3. 伤害计算内核：9 乘区连乘

移植自开源计算器（MIT，参考 JadeYingWah/WutheringWavesDmgCalc 的 damage_calc.py 思路），
**改造点：每个乘区的 Σ 不再来自用户静态输入，而来自"当前帧生效 buff 按乘区分类汇总"**。

```
最终伤害 = 基础乘区 × 加成乘区 × 加深乘区 × 防御乘区 × 抗性乘区 × 独立乘区 × 倍率乘区 / 100
暴击期望 = 最终伤害 × 暴击期望系数
```

各乘区定义（关键：哪些内部加算、哪些互相乘算）：

| 乘区 | 公式 | 内部关系 |
|---|---|---|
| 基础乘区 base | (角色基础属性 + 武器基础) × (1 + Σ百分比加成) + Σ固定值 | 攻击力/生命/防御，按 multiplierSource 选基准 |
| 加成乘区 bonus | 1 + Σ(伤害加成) | 元素加成、技能类型加成在此**加算** |
| 加深乘区 deepen | 1 + Σ(伤害加深) | **独立于加成乘区，两者乘算**。词条名带"加深"走这里 |
| 暴击期望 crit | (1 − critRate) × 1 + critRate × critDmg | 期望值展开（非"暴击/不暴击"二选一） |
| 倍率乘区 mult | (基础倍率 + Σ倍率增加) × Π(1 + 倍率增幅) | 内部：增加=加算，增幅=各自独立乘算 |
| 防御乘区 def | (800 + 8×角色等级) / (敌方最终防御 + 800 + 8×角色等级) | 敌方基础防御≈792+8×敌人等级，再算减防/穿透 |
| 抗性乘区 res | 见下 | 负抗收益减半 |
| 独立乘区 indep | Π_group (1 + Σ组内) | 组内加算，组间乘算 |

抗性乘区细则：抗性≥0 时 `1 − 最终抗性`；最终抗性<0 时 `1 − 最终抗性/2`（负抗减半）。
最终抗性 = 敌人基础抗性 − 减抗 − 穿透。

**条件增伤匹配（buff 是否作用于某段 hit）**：按三个维度打标签匹配——
- 元素：冷凝/热熔/导电/气动/衍射/湮灭
- 技能类型：普攻/重击/共鸣技能/共鸣回路/共鸣解放/变奏/延奏/声骇技能
- 效应状态：光噪/风蚀/虚湮/聚爆/霜渐/电磁 等

hit 携带这些标签（damageTag），buff 携带 filter，结算某 hit 时只汇总 filter 匹配的 buff。

**验证锚点**：本内核算出的单段伤害，应能对上 xlsx「伤害计算」页在相同配置下的数值（回归测试标准答案）。

### 3.1 权威公式来源：xlsx「伤害计算」页单元格公式（已解码，比开源计算器更完整）

**重要**：xlsx「伤害计算」页每个技能段的伤害单元格（如 D5 未暴击 / E5 暴击）本身就是一条数组公式，
内含完整乘区连乘。这不仅是"标准答案"，更是**伤害内核的权威规格**——规格与回归答案同源，无二义性。
建议直接照它翻译成代码，而非移植开源计算器。

解码后的乘区连乘（源自 D5，标签取自「伤害配置」分区名 def99/dmgchg/dmgrd/dmgampl/dmgpost）：
```
最终伤害 = CEILING(
    (技能倍率×0.0001) × 攻击面板          # 倍率乘区 × 基础面板(面板已含攻击%加成)
  × MIN(2, 1/( …/(800+等级×8) +1 ))       # def99 防御乘区，含减防/穿透，且有【2倍上限】
  × (1 + Σ伤害加成)                        # dmgchg 加成乘区
  × IF(抗≤0,1-抗/2, IF(抗<0.8,1-抗, 1/(1+抗×5)))   # 抗性乘区【三分支】
  × (1-免伤1) × (1-免伤2)                   # dmgrd 免伤乘区
  × MAX(Π(1+dmgampl1..9),0)                # 9个独立增幅乘区连乘
  × MAX(Π(1+dmgpost0..6),0)                # 7个后段乘区连乘
  × MAX(1+最终N,0) × MAX(1+最终B,0)         # 最终伤害乘区
, 1)
暴击版：dmgampl/dmgpost/最终 换成暴击专属平行行 + 暴击乘区（部分buff仅暴击生效）
```

**与开源计算器 damage_calc.py 交叉检查结论：核心结构逻辑一致，xlsx 更完整。**
一致处：均为"乘区间连乘、乘区内加算"模型；防御 `800+8×等级` 分母结构一致；负抗减半规则一致；
加成/加深/独立/暴击乘区一一对应。xlsx 多出的四处（打高抗/免伤敌人及暴击细节时需要）：
1. 抗性【高抗档】：抗性≥80% 时 `1/(1+抗×5)` 衰减（开源仅两分支）。
2. 【免伤乘区】dmgrd `(1-免伤)`（开源无）。
3. 防御乘区【2倍上限】`MIN(2,…)`（开源无）。
4. 【暴击专属平行乘区】——有些 buff 只在暴击时生效，xlsx 用整套平行行处理（开源仅单一暴击系数）。

→ **实现策略**：以 xlsx 公式为准翻译伤害内核；开源计算器作次要交叉参考（代码结构清晰，但边缘情况以 xlsx 为准）。
期望DPS 场景下，暴击用期望展开 `(1-critRate)+critRate×critDmg`，或按 xlsx 分别算暴击/未暴击再按暴击率加权（两者等价）。

## 4. 资源子系统（已冻结，以视频总结图3为准）

### 4.1 大招（共鸣解放）能量 —— on-hit，全队分配

挂载点：**造成伤害时的每一个 hit**（xlsx「大招回收」列，逐段存储，粒度足够）。

```
distributeEnergy(基础能量, dealer, others):
    dealer.resonanceEnergy += 基础能量 × 1.0 × dealer.共鸣效率
    for t in others:                                  # 另外两名队友
        t.resonanceEnergy  += 基础能量 × 0.5 × t.共鸣效率
```

三条铁律（勿写错）：
1. dealer 拿 **100% 基础值 × 自身共鸣效率**。
2. 队友各拿 **50% 基础值 × 各自共鸣效率**；**队友那50%不受 dealer 共鸣效率影响**（效率隔离，无外溢）。
3. 「不在场/后台/后摇中」都不影响——只看"是不是这段 hit 的 dealer"。dealer 得 100%，其余两人得 50%。

**合轴收益的数学来源（无需特殊加成逻辑，自然涌现）**：
合轴时 A 打技能 x、B 打技能 y，两段 hit 在同一时间窗并行判定：
```
A的x命中: A +100%(自己) , B +50%(蹭)
B的y命中: B +100%(自己) , A +50%(蹭)
→ 单位时间内 A、B 各多吃了对方 hit 的 50%
```
合轴之所以"凭空多能量"，只是因为同一时间窗内被跨过的 hit 段数更多，每段都触发一次全队分配。
这也是为何 tick 必须逐帧扫描全部三名角色指针。

### 4.2 协奏能量 —— on-cast，只给施放者

挂载点：**技能释放第一帧**（不是命中）。

```
技能释放第一帧: castChar.concerto = min(100, castChar.concerto + action.concertoGain)  # 数据源:图3能量论
```

- 上限 100，个体资源，不分队友、不打折。
- 固定值：极限闪避 +10、大招 +20；普攻/共鸣技能等按角色配置。
  **数据源 = xlsx「协奏回收」列（第21列，逐 hit 存储）** + 图3能量论的固定值口径。
  （更正：之前误判"xlsx无协奏列"，实为早先预览截断只看了前20列。协奏产出数据一直都在。）

- **⚠️ 待你裁决的口径冲突（协奏挂载时机）**：
  - 图2（视频）说协奏 = **on-cast**（释放技能第一帧生效），佐证是"大招打断E照拿协奏但无伤害"。
  - 但 xlsx 把「协奏回收」**逐 hit 存**（如优昙A3 的7段各给0.77），倾向 **on-hit**。
  - 两者可能都对但适用不同技能，也可能视频是简化。建议实测："打半个多段技能切走，协奏是全额、按已判定段数、还是只拿施放那份"。
    在敲定前，引擎把协奏事件做成**可挂 hit 也可挂 cast** 的通用时间点（与大招能量同构），别写死。
- 极限闪避是实战协奏主要来源之一（"蹭闪嫖点数"）。
- 由 on-cast 特性推出的实战 trick（可作为验证用例）：用大招打断 E，协奏照拿（施放第一帧已给），
  但因 hit 未打出，伤害与大招能量都没有。

### 4.3 破盾回能

```
敌人白条被削韧打破时: 全队每人 resonanceEnergy += 3
```
- 仅 cost4/3 的 boss 有白条（xlsx「敌对属性列表」页「白条」列 = 破盾阈值）。
- 用到 xlsx「削韧值」列的累积。boss 战能量循环必须建模；练功假人无白条可忽略。

### 4.4 建模结论

BattleState 每 tick 维护三名角色独立能量账本；每段 hit 向三人分别记账（dealer/队友份额不同）。
与"逐帧维护三名角色后台动作指针"配套：伤害看 dealer，回能全队分。

## 4B. 偏谐子系统（Tunability，3.0 新机制，v0 纳入）

**定位纠正（重要）**：偏谐是**独立于协奏/大招能量的第三套资源，且作用在敌人身上**，性质更接近削韧/白条，
属于 `enemy` 状态机而非 `characterResources`。之前误把 xlsx「偏谐值」当协奏值是错的——
xlsx「角色-女/男」的「偏谐值」列 = **该段 hit 对敌人偏谐槽的累积量**（与「削韧值」并列）。

### 4B.1 主线（v0 必做，对全角色总伤害都有贡献）

```
偏谐累积:  每段 hit → enemy.tunabilityAccum += hit.偏谐值 × dealer.偏谐效率
失谐:      tunabilityAccum ≥ enemy.偏谐阈值 → 敌人进入「失谐」状态
谐度破坏:  攻击失谐敌人 → 产生一段额外伤害(harmonyBreakDamage) + 清空偏谐值
           + 一段时间内无法再累积(tunabilityLockUntil)
```

- 强敌（boss）：偏谐值满后可能需专门的「谐度破坏技」才能结算谐度破坏；练功假人/小怪可自动触发。
  v0 可先按"命中即触发"简化，boss 的"需谐破技"作为角色特化标记后加。
- **谐度破坏伤害公式——已找到，在「伤害计算」页 R1093-1106（"其他"块）**：
  ```
  谐度破坏伤害 = 基础值 × 目标类型 × 倍率 × 目标防御公式
  ```
  关键数据（表列：谐度破坏 | 倍率 | 对失谐伤害 | 对常态伤害 | 结算次数）：
  - 按敌人 COST 分档，且**对失谐 vs 对常态目标差异巨大**（这解释了"必须先失谐才有大破坏伤害"）：
    对COST1通用 倍率16→失谐4477/常态1；对COST3 →失谐13429/常态2；对COST4 →失谐62668/常态7。
  - **武器类型影响谐破**：多数武器倍率16（佩枪/臂铠/迅刀-2/音感仪→62668），
    但个别有特殊分段（长刃-1/-2/-3 倍率1.73/2.27/12，迅刀-1 倍率1 但结算4次）。
  - 角色面板「谐破增幅」进一步放大该伤害（xlsx `伤害计算` R2C15、`角色技能类型`「谐破增幅」列）。
  → v0 直接用这张表：按敌人COST + 角色武器类型查 (倍率, 对失谐伤害, 结算次数)，乘谐破增幅。

### 4B.2 敌人偏谐槽数据（已有）

xlsx「敌对属性列表」页第21列「偏谐值」= 敌人偏谐阈值，与白条/韧性并列的三套独立敌人槽之一。
样例：朔雷之鳞（COST=4）偏谐阈值=3840，恒定不随血量变化（类似白条按等级/COST定档）。
敌人 Cost 分级（1C/3C/4C）影响偏谐上限与触发频率。

→ enemy 状态需维护三套独立槽：`toughnessAccum/白条`、`韧性`、`tunabilityAccum/偏谐阈值`。

### 4B.3 偏移-干涉-响应（v0 纳入框架，数据可后填）

这是偏谐的高级层，高度角色特化（琳奈/莫宁/爱弥斯等 3.0 角色），但受影响角色只增不减，故建入框架：

```
偏移(Shift):  特定角色给敌人挂「震谐·偏移」或「集谐·偏移」（互斥，同一目标仅存一种）
              琳奈可战前切共鸣模态选择类型；战斗中切换会清标记
干涉(Interference): 对带偏移的敌人做谐度破坏 → 偏移升级为对应「干涉」，持续约8~25秒
  ├─ 震谐·干涉: 响应角色在攻击命中该敌人时触发一次特殊攻击（如琳奈约1880%衍射追伤），
  │            视为震谐伤害，同一敌人每8秒仅1次（独立CD）。适合单体爆发。
  └─ 集谐·干涉: 响应角色对该敌人的最终伤害提升；队伍中响应角色越多提升越大。适合群体。
                （每层集谐·干涉提高琳奈"每点谐度破坏增幅"对该目标的最终增伤；
                 琳奈在队时该敌人集谐·干涉层数上限+1）
```

建模方式：把「偏移」「干涉」作为 **enemy 身上的 debuff 状态**，把「响应」作为**角色的条件触发**
（震谐响应→触发一段额外 hit，带独立CD；集谐响应→一个只对该敌人生效的最终伤害乘区 buff）。
这样它自然复用第3章的乘区体系与第6章的 buff 触发框架，无需另起炉灶。

#### 4B.3.1 响应机制模板（已用琳奈/爱弥斯/达妮娅原文验证——高度模板化，仅两种）

验证结论：偏移-干涉-响应在 wiki 原文里描述规整、可解析性甚至高于普通 buff。三个响应角色的原文
逐一证实"震谐→额外hit、集谐→最终伤害乘区"的建模方向，且字段结构在角色间**逐字同构**。
只有震谐、集谐两种响应模式，每种字段固定，逐角色只需填几个参数。

**有无响应的判定（可自动化）**：原文是否含"响应【震谐·干涉】"或"响应【集谐·干涉】"。
含 → 有响应；今汐/散华等全文无此字样 → 无响应。

**模板A — 震谐响应（单体爆发）：**
```jsonc
{
  "responseType": "震谐",
  "trigger": "队友对目标造成谐度破坏并使其进入震谐·干涉",
  "extraHit": { "name": "光谱解析/星爆/…", "damageType": "震谐", "multiplier": "<逐角色填>" },
  "cooldownPerTarget": 480,          // 8秒×60，普遍值
  "damageBasis": "谐破增幅相关（与攻击/暴击等无关）"
}
```
建模：角色的条件触发 → 产生一段额外 hit，进 tick 循环照常结算。

**模板B — 集谐响应（持续增伤）：**
```jsonc
{
  "responseType": "集谐",
  "effect": "finalDmg += 自身谐破增幅 × 0.0012 × 目标集谐·干涉层数",  // 每点谐破增幅0.12%/层
  "zone": "finalDmg(6类最终伤害)",   // 与「伤害配置」tab "6类最终伤害" 对应
  "scope": "self_vs_thisTarget",     // 仅自身、仅对该目标
  "raiseStackCapIfInTeam": 1         // 该角色在编队→集谐·干涉层数上限+1
}
```
建模：一个只对该目标生效的"最终伤害乘区"buff，值随谐破增幅×层数动态求值。

**已验证角色样例：**
- 琳奈：双模态，可施加震谐/集谐偏移（偏移持续25s，唯一可挂双偏移）；震谐响应"光谱解析"(CD8s)；
  集谐响应按模板B，在队层数上限+1。
- 爱弥斯：震谐响应"星爆"(CD8s)，结构同模板A。
- 达妮娅：集谐响应，逐字同模板B（谐破增幅×0.12%/层，在队层数上限+1）。

## 4C. 核心资源子系统（角色专属资源，新版数据发现，v0 纳入框架）

新版 xlsx 有「核心回收1/2/3」三列（第22-24列），且**几乎每个角色都用到**（达妮娅黯核、共形能量、
各类层数/形态资源等）。这是每个角色**专属的第四类资源**，与协奏/大招能量/偏谐都不同，性质各异。

```
每段 hit 结算时:
  for k in [1,2,3]:
      if hit.核心回收k 有值:
          dealer.coreResource[k] += hit.核心回收k      # 逐hit累积，多为整数(如白芷核1=1)
```

建模方式：给 CharacterRuntimeState 加一个通用的 `coreResource[1..3]` 槽，语义**由每个角色自定义**
（有的是层数、有的是能量、有的是形态计量）。核心资源的**消耗与效果**（如达妮娅黯核触发形态、
长离离火层数增伤）属于角色特化逻辑，走第6章 buff/触发框架，不塞进通用 schema。

- v0：先把 coreResource 的**累积**接进 tick（数据现成，逐hit）。
- v1：逐角色实现核心资源的**消耗条件与效果**（这是角色差异化的主要载体，也是"特殊角色逻辑"集中地）。
- 新版新增「核心回收3」说明已有角色用满3种核心资源，槽位设3是有必要的。

## 4D. 异常/效应伤害子系统（「伤害计算」页 R1027+ 发现，v0 纳入）

「伤害计算」页 1024 行后是独立的"其他"块，含一整套**元素效应（异常）伤害系统**——这是独立于技能 hit 的
**第二类伤害来源**，此前未显式建模。约7种效应，每种有持续时间、层数、逐层伤害表，部分附带 debuff。

```
异常伤害 = 异常伤害基础值 × 倍率 × 目标防御公式   （对目标；另有"对角色"版用于自伤）
```

**效应总览（数据均来自 R1028-1090）：**

| 效应 | 持续/层 | 层数上限 | 逐层附带效果 | 备注 |
|---|---|---|---|---|
| 风蚀效应 | 14.8s | 15 | 纯伤害（倍率0.45→15.75） | 重复获得刷新持续 |
| 电磁效应 | 15s | 16 | 电磁倍率 + **爆发倍率**（双段） | |

| 聚爆效应 | 15s | 16 | 纯伤害；有"模态结算"变体 | 爱弥斯/达妮娅有专属结算列 |
| 光噪效应 | 3s | 常规10 | 纯伤害，每3秒结算 | 持续短、刷新快 |
| 虚湮效应 | 25s | 12 | **减防**（-31.86→-382.32，随层数加深） | 到期清空全部层 |

**对模型的三点补充：**

1. **效应是独立伤害源**：tick 循环除了结算技能 hit，还要维护"敌人身上的效应层"，按各自持续时间衰减，
   到结算点（如光噪每3秒）产生 `异常伤害`。这类伤害走上面的异常公式，**不完全等同9乘区技能伤害**，
   需单独结算通道。
2. **部分效应附带 debuff，反哺主伤害**：虚湮的**减防**（-382 满层）直接进敌人防御乘区、霜渐的**减速/冻结**
   影响敌人行为、电磁的**爆发**是额外段。其中虚湮减防对全队技能伤害都有增益，必须建模。
3. **效应 duration 补全了第3章的效应标签体系**：之前 `damageTag.effect`（光噪/风蚀/虚湮/聚爆/霜渐/电磁）
   只是标签，现在有了每种的精确持续时间和层数机制，"对拥有【霜渐效应】的目标"这类条件buff可精确判定生效窗口。

**v0 落地**：先做效应的层数累积 + 逐层伤害结算 + 虚湮减防（对主伤害影响最大）；
霜渐减速/冻结、电磁爆发等细节可 v1 精修。爱弥斯/达妮娅的聚爆"模态结算"变体属角色特化，逐角色填。

### 5.2 动态：边（Transition，运行时求值而非静态存储）

边的权重不是常量（同一技能在不同 buff 下伤害不同），因此是函数：

```
getLegalTransitions(state):
  在当前动作的可派生/可脱手帧位，枚举满足 precondition 的候选动作
  候选类型包括：接续技能、切人(switch)、大招打断、声骇技能打断
  对每个候选: newState = applyAction(state, action); yield (action, newState)
```

### 5.3 中断优先级（来自视频图1，叠加在派生/脱手之上）

高优先级动作可强插打断低优先级动作的后摇，即使后者不在派生窗口：

```
大招 R（最高，强制进入大招动画）
  > 声骇技能 Q（打断技能后摇）
    > 特殊变奏技能（可打断 R/Q 打断不了的"长脱手"动作）
      > 常规技能（打不断其他技能）
```

→ 边的合法性 = (在派生窗 OR 可脱手) OR (候选动作中断优先级 > 当前动作)。

### 5.4 切人边（switch）的特殊结算

```
switch(from → to):
  前置：switchCooldownRemaining == 0
  效果：
    1. from 的当前动作【不打断】，转入后台继续走完后摇（关键！合轴基础）
    2. switchCooldownRemaining = 60（1秒CD）
    3. 变奏/延奏判定（读 from 自己的协奏槽）：
       if from.concerto 满:
          触发 from.outro（延奏：留team buff到lingeringEffects）
             + to.intro（变奏：入场特殊攻击，含hits）
          按规则扣除 from.concerto
       else:
          普通切人，无变奏/延奏
```

**延奏 vs 变奏**（图4厘清）：均由"协奏满时切人"触发；
延奏=离场角色给全队/下位上 buff 或生成特殊效果；变奏=上场角色自动放一个入场特殊攻击（可触发核心机制）。

```jsonc
  "id": "buff_xxx",
  "sourceType": "skill/circuit/passive/echoSet/weapon/outro",
  "category": "bonus/deepen/crit/mult_add/mult_boost/atkPct/flatAtk/resShred/defShred/finalDmg/indep_groupN",
  "zoneNumber": 2,               // 作者编号乘区(类0-6)，与category互为校验
  "value": 0.12,
  "filter": { "element": [...], "skillType": [...], "effect": [...] },
  "maxStacks": 3,
  "scope": "self/team/onfield/introChar/outro",   // ← 伤害配置tab作用域文本可解析
  "trigger": { "condition": "...", "target": "..." },
  "duration": 720,               // ⚠️ 解析原文"持续N秒"×60；无则常驻(∞)。见6.1
  "onSwitchOut": "persist"       // 默认persist；仅原文明写"切换角色/离场则失效"时=clearOnSwitch。见6.1
}
```

**收窄后的护城河——只剩给已分类 buff 补两列：**

1. **`duration`（生效时间窗）**：静态计算器与时间轴模型的本质差异——它只管 buff 开/关，不管持续帧数。
   部分文本有"持续12秒"可提取，其余从 wiki 补。**这是时间轴模型不可回避的增量工作。**
2. **`onSwitchOut`（切走失效规则）**：无独立字段，但可从 scope 反推线索
   （"角色延奏"→persist；"前台角色"类→大概率切走失效），再逐个人工确认。

其余（category/数值/层数/触发条件/作用域）已由「伤害配置」buff 库提供，
建议**直接导出2600条作为 buff 库基础**，在其上补 duration 与 onSwitchOut 两列。

数据源分工：
- **xlsx「伤害配置」buff 库**：category(乘区)、数值、maxStacks、触发条件、作用域——**主源，~2600条**。
- wiki（库街区）：补 duration（持续时间）、及 buff 库未覆盖的最新角色效果原文。**逐级倍率永久不需要**（锁满级）。
- 开源计算器：乘区公式与条件增伤标签匹配逻辑的**次要交叉参考**（核心公式以 xlsx 3.1 解码版为准，MIT）。
- xlsx其余页：帧、取消点、可脱手、逐段资源、面板、敌人槽、验证答案。
  （协奏产出见「协奏回收」列，逐hit；固定值口径参图3能量论。）

### 6.1 duration 与 onSwitchOut 的解析规则（已用散华验证）

**核心决策（onSwitchOut，永久规则）**：
> **只有 buff 原文明确写明"切换角色/离场则失效（提前结束）"的，才 clearOnSwitch；未提及的一律默认 persist（切走不掉）。**

理由：鸣潮文案对"绑定持场角色、切走即掉"的 buff 基本都会显式写明；没写的默认视为不受切人影响。
这把 onSwitchOut 从模糊推断简化为一条可自动化的二分规则。

**duration**：鸣潮文案标准句式"持续N秒"，几乎每个有时限 buff 都明写 → 正则解析 `持续(\d+)秒` → ×60 得帧数。
无"持续"字样者：声骇2件套等常驻加成 = 永久(duration=∞)；"直到下次触发"类另行标记。

**解析伪代码：**
```
parseBuff(原文, scope):
  duration = match(持续(\d+)秒) ? int×60 : (常驻类?∞ : 需人工确认)
  onSwitchOut = 原文含("切换至其他角色"|"离场"|"该角色在场时"|"提前结束") ? clearOnSwitch : persist
  category = xlsx buff库已给(加深→deepen / 加成→bonus / 攻击→atkPct ...)
```

**验证样例（两个真实案例，覆盖两种 onSwitchOut）：**

样例A — 散华6链（onSwitchOut 靠默认规则）：
> 原文："引爆【冰棱】或【冰川】后，队伍中的角色攻击提升10%，持续20秒，可叠加2层。"
```jsonc
{ "category":"atkPct", "value":0.10, "scope":"team", "maxStacks":2,
  "duration":1200, "trigger":"引爆冰棱/冰川", "onSwitchOut":"persist" }  // 原文未提切人失效→默认persist
```

样例B — 散华延奏（onSwitchOut 原文明写）：
> 原文："下一位登场角色…普攻伤害加深38%，效果持续14秒，若切换至其他角色则该效果提前结束。"
```jsonc
{ "category":"deepen", "value":0.38, "scope":"introChar",
  "duration":840, "onSwitchOut":"clearOnSwitch" }  // "若切换至其他角色则提前结束"→明写clearOnSwitch
```

**数据可靠性提醒**：库街区官方 wiki 是动态渲染（直接 fetch 只得 meta），批量抓 buff 原文需走其后端 JSON API
（浏览器 Network 面板找真实接口）或用可执行 JS 的爬虫（Playwright/Puppeteer），勿静态爬 HTML。

## 7B. 相关项目与外部资源参考

调研过的同类项目与可复用资源，按"能给本项目什么"归类。核心增量（逐帧 tick 仿真 + 合轴/后台并发/能量循环自动涌现）
是以下所有现有项目都未做到的部分——它们的价值在 UI/数据/公式/工程规范的参考，不构成对本项目差异化的替代。

**椰果工具箱（d4rkOfficial/wuwa-afyg-tool，MIT）—— 最接近的对标（已读码确认）**
- 现代 Web 工具（SvelteKit5 + TS + Tailwind + Vite，部署 Vercel/CF Pages）；功能：拉表、排轴、配装对比、逐段伤害/DPS/占比。
- **读码确认（compute.ts + timeline.store）：不做时间轴仿真**——`computeAll` 逐段独立计算（每段套用户手动绑定的buff再求和）；
  全 src 搜"能量/协奏/帧/fps"**均0命中**（不建模能量系统、无帧概念）；DPS 分母来自用户手动放置的"时间参考线"。
  即"拉表(逐段手动配buff)+可视化排轴(手动摆块标时间线)+求和"，正是本项目要超越的那类工具的最精致版。
- **本项目差异化由此坐实**：后台后摇并发、合轴凭空能量、能量循环仿真椰果全无——尤其"不建模能量"意味着它
  **答不了"这条轴大招循环转不转得起来"**，而这正是真实配装择优的关键约束，是本项目 tick 仿真的核心价值。
- **意外收获——第三方印证本项目伤害内核**：椰果 computeResultEntry 乘区连乘与 xlsx 解码公式（3.1）结构一致；
  且其集谐干涉增伤 `1+0.0012×谐破增幅×层数` **与本项目集谐响应模板B（4B.3.1）逐字一致**——模板B 现有"wiki原文+可运行实现"双重印证。
  同时再次确认 xlsx 的抗性高抗档 `1/(1+抗×5)` 是椰果所无（本项目以 xlsx 为准正确）。
- 可借鉴工程点：① `CharAccum` 面板累加器（flat/pct攻血防+暴击+共鸣效率+谐破增幅+偏谐效率+元素/类型加成）可作面板聚合层参考；
  ② 分段DPS/伤害占比的结果页逻辑（按参考线切段、每段求和、按角色分摊）；③ AGENTS.md 协作规范范本。
- 在线站：wuwa-afyg-tool.vercel.app。

**Nanoka API（ww.nanoka.cc，椰果工具箱的数据源）—— 干净的元数据/文本源**
- REST：`/api/v1/list|info|icons|recommend/{character|weapon|echo|echo-set}`，传中文名返回详情，随版本自动更新。
- 取用价值：角色/武器/声骇的**元数据、技能/buff 描述文本、图标**——比爬库街区 wiki 干净（解决动态渲染难爬问题）。
- 局限：**无帧数据/无逐段资源**（那是本项目 xlsx 独有）。定位=替代 wiki 的"buff文本/图标/元数据"层，与 xlsx 组合使用。

**JadeYingWah/WutheringWavesDmgCalc（MIT）—— 乘区公式次要旁证**
- 静态乘区计算器（PyQt6）。9乘区公式与条件增伤标签逻辑可作交叉参考，但核心公式以 xlsx 3.1 解码版为准（更完整）。

**开源数据源组合建议**：xlsx（帧/资源/倍率/敌人/公式，权威）+ Nanoka API（最新buff文本/图标/元数据）
+ 库街区（Nanoka 未覆盖时的兜底原文）+ 两个开源计算器（公式旁证）。
