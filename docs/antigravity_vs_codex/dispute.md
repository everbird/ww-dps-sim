# Antigravity 与 Codex：分歧

只比较 2026-11-08 的 [Antigravity 评审](../overall-review-antigravity-20261108.md)（v2）与 [Codex 评审](../overall-review-codex-20261108.md)（同日独立复核更新版），不复查代码、其他资料或游戏事实，也不裁定哪一方的技术判断正确。

每项先标明分歧的类型（定性、证据标准、方法、优先级……），再列双方观点、差异在哪，必要时补一句"判读边界"，说明这项分歧不能被夸大到什么程度。有些分歧只是诊断重心或推进顺序不同，两边可能同时成立，不应读成互相否定。一方独有、另一方没有明确表态的方案放在 [blindspot.md](blindspot.md)；双方一致的部分见 [consensus.md](consensus.md)。

比较以两文最终保留的观点为准。Codex 在文中明确更正了初稿的两处判断（"切人之后协奏立即为 0"的示例、校准时钟问题的定性力度），这里按更正后的立场列。

## D01. 现在卡住进展的主要症结是什么

**类型：诊断重心不同，两者可能同时成立。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 内核已经很扎实。真正让人陷入"实测校准泥潭"的，是在没有状态锚定的情况下，用自由推演去硬拟合 3 分钟的录像：排轴语法和调度器被补位、`!`、`敌人 失谐`、`能量满` 等"录像黑魔法"污染，形成恶性循环。这一条标为"最严重的架构反噬"，破局的第一根支柱是底座双模化。 |
| Codex | 首先要打通"数据 → 执行 → 报告 → 结论"的可靠性：现有结果可能把失配、截断、外推或丢失的实例伪装成完整确定的解释（R09–R11 等）。"增加更多实测无法直接修好这两类问题，增加一个查询 API 也不会自动修好。" |

**差异所在**：Antigravity 把录像场景的写法和调度器之间的相互干扰列为头号问题；Codex 把汇总、比较这一层的信息丢失和边界不一致列为第一批要处理的。

**判读边界**：两者指的是不同的层，一个是录像剖析的输入写法，一个是汇总与比较的输出，文本没有互相反驳。Codex 没有评价补位造成的干扰；Antigravity 没有提到 R09–R11 这类输出问题。

来源：[Antigravity §0 第 2、3 项、§2.2 症结一](../overall-review-antigravity-20261108.md)；[Codex §9.2 末段、§13.2](../overall-review-codex-20261108.md)。

## D02. 录像剖析里的补位和强制指令应该怎么对待

**类型：处理方式不同；Codex 没有直接评论双模提案。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | `A1~ A2~ A3~ A4~` 是"假补位"：会真实结算，凭空生成录像里没有的回路、协奏和能量。`能量满`、`敌人 失谐`、`敌人 换` 让本该只描述"玩家按键序列"的排轴 DSL，"变成了混杂着状态补丁的胶水脚本"。应另设锚定观测模式，用空转等待和状态同步锚点代替，让录像场景里这些写法"全部消失"。 |
| Codex | 把"有空补位、等判定出手、自动谐破、额外操作延迟"归为调度策略（"本次采用的操作方式选择了等待或插入"），把 `at` 对时、能量满、指定失谐归为用户或录像给定的条件（"这是输入的一部分"），要求说明它们限制了哪些预测。保留 T6–T7 的现有调度取舍，不要求重写内核。 |

**差异所在**：Antigravity 认为这些写法是污染，要移出排轴语法；Codex 把它们当作正当的输入或策略，要求的是分类和标注。

**判读边界**：Codex 没有否定"锚定观测模式"，只是没有提出。两者都同意强制给定的状态不能算作引擎的预测（[C09](consensus.md)）。另外，对"锚定之后还能得出什么"，两边的乐观程度不同：Antigravity 认为补齐状态时得到的 `syncResidual` 汇总就是"最精准的校准清单"；Codex 强调被指定的量不能再拿来证明模型能自己预测对。两句话针对的对象不同，未必冲突。

来源：[Antigravity §2.2 症结一、§3.2](../overall-review-antigravity-20261108.md)；[Codex §3.3、§7 倒数第二段、§10](../overall-review-codex-20261108.md)。

## D03. `loop` 时钟口径：是代码 bug，还是文档契约冲突

**类型：定性与修法不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 定为 Bug。schema 注释和 `points.yaml` 都要求用训练场录像量世界秒，代码却返回战斗秒。举例：心队一轮是 30.57 战斗秒，对应约 43 世界秒，照说明填进实测会"平白无故报出 13 秒的巨额偏差"。应改成 `(span.endF - span.f) / 60`，或者同时输出、显式区分两种时钟。 |
| Codex | 取值已复现，但更正了初稿的判断力度：TD-11 §1.2 说"一轮几秒"通常指战斗秒，`summary.ts` 的分轮也按战斗时钟。问题首先是不同文档和字段契约互相冲突，"不能据此直接把 `endT - t` 改成帧差"。应在观测里写明时钟，规定旧字段的默认含义，再检查各消费者。目前登记的 37 个点都是面板或跳字，`game` 都是 null，不能说已经有实测时长被判错。 |

**差异所在**：Antigravity 以 schema 注释为准，认定代码错了；Codex 指出另有文档支持战斗秒，哪边为准要先定契约。对后果的说法也不同：Antigravity 描述的是将来填进世界秒实测时会出现的偏差，Codex 指出目前还没有这样的实测点。

**判读边界**：两者都接受显式区分两种时钟（[C12](consensus.md)），分歧只在"要不要直接把现有算法改成世界秒"。裁判没有核对 TD-11 原文。

来源：[Antigravity §2.2 症结四、§7 P0 第 1 项](../overall-review-antigravity-20261108.md)；[Codex §4 R01](../overall-review-codex-20261108.md)。

## D04. 几个数据源互相吻合，能不能把数值认定为可信、不用再实测

**类型：证据标准不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 倍率、能量消耗、协奏值、动作发生帧 / 结束帧都算静态数值，用 `nanoka-check` / `wuwalab-check` 自动三角互证，三方吻合的"直接定为 `Tier-1 可信`，零人工实测"。公式层"严格对齐表格 Golden 夹具"，单人无 buff 的裸跳字和实机误差 < 0.05%。 |
| Codex | 由同一份资料驱动的实现和参照一致，不能同时证明上游资料没错；同一上游被几个网站转载，不能当成几份独立的支持；也不宜给整个网站一个统一的概率分数。"协奏 +10"的数量有出处，不代表"首次命中时到账"的时机也有出处，时机应单独标为推断。3418 条公式夹具逐位对拍，证明的是与 xlsx 里保存的参照一致，"不是 3418 次独立游戏实测"。构建与交叉核对"支持定位，不等于所有来源都是独立真值"。 |

**差异所在**：Antigravity 把多源一致当作可信的充分条件；Codex 要先看这些来源是否独立、证的是数量还是时机。动作帧数和资源到账时机是两边最明显的交汇点。

**判读边界**：Antigravity 没有讨论那"三方"彼此是否独立；Codex 也没有具体否定某一项三方吻合的数据。

来源：[Antigravity §2.1 第 3、5 项、§4.1](../overall-review-antigravity-20261108.md)；[Codex §2.1、§5.1、§13.1、§13.3](../overall-review-codex-20261108.md)。

## D05. 对上一次，能把多大范围"锁死"

**类型：验证结论往外推的标准不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 漏斗的规则是"上一级没锁死之前，绝不看下一级"，第一级做到"误差 < 0.05% 永久锁死"。开场单人时心召唤-6 录像 8444、仿真 8448，据此判定"第一级 100% 锁死，心自身面板、词条、公式零误差"。 |
| Codex | 每条规则要记下它已被支持的条件：一次单独命中对齐，不能自动覆盖 buff 刷新、后台触发和取消之后的行为；用具体的验证覆盖情况代替整个引擎的单一"准确率"；受控短实验支持的是特定条件下的时机、资源和数值，推不出所有角色和上下文都通用。 |

**差异所在**：Antigravity 允许把一次精确对上推广成这一层的永久结论，然后进入下一层；Codex 要求结论只覆盖实际检查过的条件。

**判读边界**：Codex 没有针对 8444 / 8448 这个例子发表意见，两边对这个读数本身没有争议，分歧在于往外推多远。

来源：[Antigravity §5 图、§5.1 悬案一](../overall-review-antigravity-20261108.md)；[Codex §2.2、§8 表](../overall-review-codex-20261108.md)。

## D06. 排查能不能保证锁定唯一的原因

**类型：对可辨识性的预期不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 漏斗每一级对不上时，"原因 100% 锁定在"这一级列出的几类里；"每次只解单变量方程"。训练场 2 分钟就能把心的两条相差项"抓个正着"；一个木桩实验"当场就能锁死 `summonCountsAsChar` 开关"。 |
| Codex | 目标是尽量设计出能区分的观察，"不能承诺从缺少区分信息的材料里唯一恢复真实机制"。相同的总量可以对应不同机制（起手给、命中给、各给一半）；候选之间只差 1 帧、而定位误差有 3 帧时，应改进量法或保留一个范围。收敛的结果可以是"现有观测无法区分"或"超出当前模型范围"，不强行把残差调到零；所有候选都解释不了时，先查量法和遗漏的机制，"不把最接近者直接定为真"。 |

**差异所在**：Antigravity 靠"每级对不上就一定出在这一级"的设计来保证定位唯一；Codex 把"无法区分"当作正常、需要管理的结果。

**判读边界**：Antigravity 的"100%"有前提，即上一级已经锁死（见 D05）。Codex 没有逐条评论 Antigravity 的两个悬案。

来源：[Antigravity §0 第 3 项、§5、§5.1](../overall-review-antigravity-20261108.md)；[Codex §6、§6.4](../overall-review-codex-20261108.md)。

## D07. 只做单变量实验，还是也要做交互组合

**类型：实验设计的程度不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 核心铁律是"永远用单变量切片替代整局猜测""每次只解单变量方程"；第二级的做法是"固定单次命中，逐一叠加单个队友 Buff"。 |
| Codex | 怀疑有交互时，要比较无效果、A、B、A+B 等必要条件；单独观察 A 和单独观察 B，不足以证明两者同时存在时的规则。按结论的需要选少量组合，不做没有边界的全排列。 |

**差异所在**：Antigravity 的方法默认各因素都能逐一隔离；Codex 明确指出，检验交互要用组合条件。

**判读边界**：Antigravity 的"逐一叠加"本身也会产生 A、A+B 这样的累积条件，只是没有把"检验交互"列为目的。两者都反对在整局里多变量盲猜（[C10](consensus.md)）。

来源：[Antigravity §0 第 3 项、§5](../overall-review-antigravity-20261108.md)；[Codex §6.2](../overall-review-codex-20261108.md)。

## D08. 排查流程按什么来组织：按机制层级，还是按时间先后与依赖

**类型：方法框架不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 四级正交收敛漏斗：① 静态面板与单下裸跳字 → ② Buff 与乘区（比值指纹、局内面板）→ ③ 单段的资源收支 → ④ 局部帧时序（按切人边界把时钟归零）。上一级锁死才看下一级，时序排在最后。 |
| Codex | 八步流程：确认可比（时钟、单位、配装、版本、敌人、环境、初态）→ 一对一匹配对象 → 分开各项残差 → 找最早有证据的偏差 → 沿依赖缩小范围（字段上次在哪变的、直接原因是什么）→ 列候选 → 选能区分的观察 → 固化结果。 |

**差异所在**：Antigravity 按"静态 → 乘区 → 资源 → 时序"的层级逐层隔离；Codex 先确认可比和对应关系，再从时间上最早的偏差出发沿依赖链往回查，不规定先查哪一层。

**判读边界**：Antigravity 的四级主要用于重新设计的隔离实验；Codex 的八步同时用于比较已有的录像和模拟结果。两边处理的材料不完全一样，文本也没有评论对方的顺序。

来源：[Antigravity §5](../overall-review-antigravity-20261108.md)；[Codex §7](../overall-review-codex-20261108.md)。

## D09. 敏感度矩阵显示影响小，能不能据此"永远不测"

**类型：结论的保守程度不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 某个开关翻过来后，既不断轴、对照场景的收益差又 < 0.5%，就"直接放过，永远不进游戏测它"；只测会让配装 / 打法结论反转或导致断轴的。 |
| Codex | 一次只翻一个开关的敏感度分析，不保证所有未知机制组合下都稳定，结论要注明实际检查过的范围；"所试单项都稳定"不等于所有机制组合都稳定。影响小的"按 T16 登记，延后实测"。 |

**差异所在**：Antigravity 给出定量阈值，并永久排除；Codex 指出单开关扫描覆盖不到组合，影响小的只是延后，不是排除。

来源：[Antigravity §4.2](../overall-review-antigravity-20261108.md)；[Codex §6.3、§13.2](../overall-review-codex-20261108.md)。

## D10. `fit` 的总分还要不要

**类型：评分做法不同；双方都同意总分会掩盖互相抵消的错误（[C07](consensus.md)）。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 把 `video.hits`（单下跳字误差）加进评估；把翻转假设开关（`flipsOf`）和改剧本动作（`neighborIter`）分开展示；按跳字 / 切人时序 / 资源"分维度打分（……互不相加抵消）"。 |
| Codex | `Fit` 已有的分项信息继续使用。改进的重点是先建立合理的对应（一对一匹配），显示缺失与歧义，再看各通道的差异；"总分继续用于候选排序"，但不能用一项变好去抵消关键规则的反证。 |

**差异所在**：Antigravity 主张各维度不再相加；Codex 保留总分做排序，把重点放在匹配是否正确。两边指出的 fit 缺陷也不重叠，见 [B-A05](blindspot.md)、[B-A06](blindspot.md)、[B-X08](blindspot.md)。

来源：[Antigravity §2.2 症结五、§7 P0 第 2 项](../overall-review-antigravity-20261108.md)；[Codex §4 R03/R06 一节](../overall-review-codex-20261108.md)。

## D11. 状态查询接口怎么建

**类型：实现路径不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | 把 `timeline.ts` 里分散重建的 `resourceTracks`、`forte`、`cooldowns`、生效的 buff 实例（含层数与剩余帧）、敌人异常层数，以及当时刻的合成面板，封装成引擎的标准纯函数 `inspectStateAt(res, frame)`；`kernel.ts` 每帧已经在记 `ForteStep` 和 `CooldownStep`。 |
| Codex | 展示用的轨道不是完整存档：回路显示主要是变化时记下的说明文字，不等于钩子的全部内部变量；回路和冷却轨道主要在 P6 采集，不能直接当作 P1 之前的快照；日志里的先后，和钩子处理事件时看到的状态不是一回事，逐条套回去得不到每个钩子实际读到的状态。第一版 `stateAt` 应从相同输入重算到指定边界、读执行器的状态，之后再考虑快照和分支；查询边界要先定好（世界帧 f 开始、P1 之前）。 |

**差异所在**：Antigravity 以现有的输出轨道和结果 `res` 为基础来组装；Codex 认为这些轨道不够格当状态 API，主张重跑执行器取状态，并且先定边界。

**判读边界**：Antigravity 的签名 `inspectStateAt(res, frame)` 以运行结果为输入，Codex 的第一版以"相同输入重算"为基础。两边都没有说明对方的方案在什么范围内不够用。

来源：[Antigravity §2.2 症结三、§6 第 2 项](../overall-review-antigravity-20261108.md)；[Codex §3.2、§4 R04/R08、§13.2](../overall-review-codex-20261108.md)。

## D12. 路线的先后，以及进游戏实测放在第几步

**类型：优先级不同。**

| 一方 | 原文观点 |
|---|---|
| Antigravity | P0 修校准口径与 fit 评分 → P1 用靶场 2 分钟的单变量实验结案深塔录像的悬案（"止血"），按敏感度排序实测，测完钉进 `assumptions.ts` 与 `tests/calibration.test.ts` → P2 补运行时因果链与统一的状态查询 → P3 分离自由推演与锚定观测。 |
| Codex | P0 量尺与结果状态（时钟、实例身份、统计边界、完成范围、缺失的观测）→ P1 执行可查（直接原因、独立的诊断通道、重算查询）→ P2 差异可定位 → P3 规则有证据（来源、候选表、整理旧证据、独立检验）→ P4 调用与效率（统一接口、快照恢复）。这些问题"能用软件小案例推进，不能一概转化为'还要进游戏测'"。首批案例：世界秒 / 战斗秒；双提供者的同名 buff 与同帧到期；致死一击、截断、锚点全部失配；散华 E 与焰痕；卜灵的协奏时机（故意保留为未解）。 |

**差异所在**：Antigravity 把进游戏的单变量实验放在第二步，用来尽快结案现有悬案（心的 8%、无归的谬误、五雷荡煞阵叠霆心域）；Codex 把规则证据放在第四批，先做纯软件就能验证的工具与执行问题，并优先整理已有材料。Antigravity 的最后一步是双模，Codex 的路线里没有对应的一项。

**判读边界**：两边的 P0 相近（[C11](consensus.md)）。Codex 说"不必等它们全部解决才设计查询接口"，所以它的顺序也不是严格串行。
