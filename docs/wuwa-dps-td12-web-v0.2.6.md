## 0. 要点

1. **只在本机用**：生成数据（`data/generated`）不进 git、不发布，网页直接读仓库里的文件。`pnpm web` 起开发服务器（`http://localhost:5317/`）；`pnpm web:build` 打包到 `out/web/`（含数据，不要发布）。
2. **七页**：场景（编辑、运行，看时间轴页面，可切换原版与视图 A–E）、结论、对比、副词条边际、声骸择优、轴搜索（v0.2.6）、视图说明；结果与 `pnpm sim` / `insight` / `compare` / `marginal` / `optimize` / `search` 相同（同一套引擎与分析函数）。
3. **引擎在 Web Worker 里跑**：择优要十几秒，页面不卡。
4. **改动存在浏览器**：场景与库存的编辑存在 localStorage，不写回仓库；要留下就"下载"后放回 `scenarios/`、`inventory/`。
5. **时间轴有六种看法，都保留**（v0.2，用户 2026-10-12 定；v0.2.4 加了 E，和 D 用一阵再定留哪个）：原版（含调试表）与视图 A–E 关注点不同，按需切换；网页与 `pnpm timeline --view` 用同一份模板与数据，同样输入得到逐字节相同的输出。
6. **用域名访问**：Vite 只认 localhost，用域名打开时把域名写进环境变量 `WEB_HOSTS`（逗号分隔），如 `WEB_HOSTS=example.com pnpm web --port 8014 --host 0.0.0.0`；不写死在仓库里。

### 2.1 时间轴的视图 A–E（v0.2；E 是 v0.2.4 的原型）

原版的问题（2026-10-12 截图看到的）：buff 34 行、每行 13 像素，标签挤在一起被截断；动作名放不下就截掉；"等待"一行几乎一整条（派生窗口、优先级这类正常节奏也画了）；能量协奏太矮、没有刻度。四种视图各从一个角度解决：

| 视图 | 一句话 | 适合 |
|---|---|---|
| A 精修泳道（`a-lanes.html`） | 结构同原版；动作名放不下挪到条下方的标签行；只画"卡住的等待"（不含派生窗口、优先级、连段、同一 tick、写轴要求的）；buff 按受益人分组、缺省只列影响伤害的，标签栏写全名与稳态覆盖率 | 想要原版但更好读 |
| B 角色分卷（`b-volumes.html`） | 每个角色一卷：动作、每段伤害（线性柱高）、能量协奏、身上的 buff；buff 用"给的人"的颜色；共用吸顶时间轴，可以放大到某一段上场 | 研究一个角色的伤害构成与 buff 覆盖 |
| C 指令表格（`c-ledger.html`） | 一行一条指令：开始、到下一条、伤害、之前卡在什么（卡住的高亮，正常节奏淡化），最后一列是本轮甘特条，等待画成斜纹 | 对轴、对视频、调排轴 |
| D 概览与透镜（`d-lens.html`） | 顶部全程导航（每秒伤害堆叠柱，拖动选范围、点一下挪视窗、− ＋ 缩放，斜线连到下方放大的那段，和下方不对齐）；主图里另有一条对齐的每秒伤害；右侧步进区与检查器 | 看单个瞬间的伤害构成、逐段过轴 |
| E 播放器（`e-player.html`，v0.2.4 原型） | 类比视频播放器 / 剪辑窗口：上面大块是"这一帧的画面"（v0.2.5：顶上一条敌人，像 boss 血条），中间播放控制，下面是扁长的时间轴（全程导航 + 三人泳道 + 敌人量表）；悬停只出预览小窗，点一下或拖动才跳帧 | 逐帧调试：对轴、查某一刻为什么这样 |

D 的步进区与检查器：

- **步进**：◀ ▶ 或键盘 ← →，单位可选命中、动作开始、切人、战斗秒、一帧；Shift + ← → 按 1 战斗秒，`,` `.` 按 1 帧，Esc 解锁。步进时自动锁定光标，走出范围时视窗跟着平移。手机上屏幕底部另有一条步进条（§3.2）。
- **上一个 / 当前 / 下一个**：三行并排写出各是什么（如"当前命中 第 177 / 455 个：椿 盛绽·A2-2，期望 6,288"）、相差几秒，上下两行点了也能跳；主图上标出当前步（命中画圈、动作描边、切人画三角）。
- **检查器**：那一刻每个人的动作（v0.2.3：动作下面两个折叠框——"给的"：这个动作给的协奏、能量，按资源分组、每行一个出处，给队友的写在第二行，提示里是原文、每段多少、第几秒；"打出的"：这个动作打出的伤害，逐个判定，判定在别的组里的、由队友命中触发的注明）、能量协奏、身上的 buff；敌人的偏谐值与白条（当前 / 上限）和状态（失谐、瘫痪）；最近一段伤害的乘区拆分与生效的加成。
- **buff 折叠**：每人收成一行合计（按乘区 + 条件合计，取最大的三项），鼠标悬停浮出清单，点一下钉住就地展开（触摸屏只用点）；清单每行的出处（原文）在提示里。
- **说明收进 ⓘ**：键盘操作、导航的含义、敌人量表的含义；悬停显示，点一下钉住。
- **共鸣回路**（v0.2.4，2026-10-19 用户要的）：每人的能量、协奏原来是两行进度条，改成一排小格子（名字、值，底边细条是满了多少，满了描边），后面接共鸣回路的核心资源（只列这次有变化的槽：心的应世心 / 照世心、雷主的电涌、卜灵的卦象、散华的透视…）；值从资源曲线的采样（30 帧一次）改成逐帧精确（时间轴模型的 `resources`，TD-10 §5.1）。核心资源说不清的状态由角色模块的只读显示钩子 `forte` 给一行（TD-08 §3.1），按" · "拆成小标签：卜灵（卦象的排列，空位 ○；少阳 / 少阴 / 阴阳相生；开阵时雷法第几阶、冲击波几次）、心（应世相 / 照世相、心相心生、统御众机、了尘愿 / 承天则能不能用、电磁+1、敕令、霆霓、霆心域、额外能量、活字心锁）、椿（白椿 / 红椿、含苞与酣梦层数、红椿·蕾）、散华（场上的冰）；维里奈、雷主只看核心资源。

E 的帧画面与操作（v0.2.4，2026-10-19、20 用户要的；原型，内容和布局按用起来的感觉再收敛）：

- **时刻条**：第几帧、战斗秒；轴里的哪一条（在等的那一条或最近执行的那一条，高亮第几个动作）；在等什么（"在等：…（已等 N 帧）"，出招节奏另写）；时停、失谐、瘫痪、"写了变奏没变奏"的标签。
- **每人一张卡片**：动作与开始后第几帧；资源与共鸣回路（同 D）；冷却（还要几秒，按次数充能的写还剩几次；时间轴模型的 `cooldowns`）；这个动作给的资源与打出的伤害（折叠框，同 D）；加成与状态 buff（剩余战斗秒，常驻的只写个数）。
- **敌人**（v0.2.5，2026-10-20 用户提议：打 boss 时血条在屏幕上方，借这个习惯）：帧画面最上面一条通栏，下面才是三张角色卡。左边敌人名、来源与等级、状态（正常 / 失谐 / 瘫痪）；中间三条横条——"血条"（没有血量这个数，按全程总伤害当血量，第 g 帧已打出的部分从满往下扣，旁边写剩多少）、偏谐值、白条——与异常效应的层数和额外层（跟着附加、定时结算、被消耗、到时更新，`shared.js` 的 `D.effects`，TD-06 §18）；右边一行概括这一帧的命中或附近（40 帧内）最近的一段伤害，点开（或悬停）看这一帧的各段、最近一段的乘区拆分与生效的加成（同卡片里的折叠框，钉住后步进也保持展开）。窄于 1100 像素时伤害那一行挪到横条下面，手机上整条上下排。原来是卡片右边一列（v0.2.4）。
- **播放控制**：按命中 / 动作开始 / 切人 / 战斗秒步进（← →，Shift 按 1 战斗秒），逐帧（`,` `.`），0.25×–2× 播放（空格开始 / 暂停，按世界时间走，放到视窗右边时视窗跟着走）。
- **时间轴**：全程导航（同 D）；放大的一段是每秒伤害、三人泳道（动作条，放不下的名字只在预览里看）与敌人量表；光标顶上有播放头的把手。鼠标悬停只出预览小窗（像视频的缩略图：时刻、谁在前台、三人的动作与能量协奏），点一下或按住拖动才跳帧。触摸屏没有悬停：点一下跳；单指横拖逐帧拖，拖的时候手指上方出预览、松手收起，从光标附近（左右 24 像素内）拖起光标不跳；双指捏合缩放。
- 手机：卡片上下排，时间轴挪到帧画面上面，播放控制固定在屏幕底部。

**角色的颜色**（v0.2.4）：每人一种颜色 `--c0..--c2`，用元素色；同元素的换深浅（`shared.js` 的 `teamColors`，原版 `timeline.html` 同样处理）——第一个用元素色，第二个往前景色 `--ink` 混 35%（深色主题变亮、浅色主题变暗），第三个往卡片底色 `--panel` 混 25%（方向相反）。心 · 雷主 · 卜灵三人都是导电，以前三条泳道同一个紫。对页面底色的对比度深色主题 ≥ 3.7、浅色主题导电 3.2（最差的衍射、气动排第三个时约 2.3）。

| 命中提示（B、原版，D 的按命中步进与"最近一段伤害"） | 钩子生成的判定写怎么来的：协同攻击写"由 椿 盛绽·A3 命中触发"（本人触发的不写角色名）；其余写引出原因，归到的动作与判定所在的组不同时前面加"由 X 引发"——"由 重击居合 引发：重击爆裂引爆（散华.引爆计时 到时）"、"5 链：冰到时自爆（散华.冰棱 到时）" |
| 出处的名字 | "起手即得"（资源公式的常数项，提示里写由来，TD-01 §3.7）、"E-引爆冰棱 命中（5 链：冰到时自爆）"、效果 id、钩子的说明；伤害明细里由队友触发的写"触发：椿 6 段、维里奈 1 段、散华 1 段" |

**轴可能有问题**（v0.2.3，2026-10-18 用户要的）：排轴里写了 `switch <角色> 变奏`、实际没变奏的切人（`warning` 的 `introMissed`，TD-09 §3.5）——各视图顶上一条提示条，点一条跳过去（A、B 换到那一轮，B 放大到切人前那一段；C 滚到那一行；D 光标落在那次切人上）；切人处画红色虚线和"!"（悬停看原因）；C 那一行标红、原因写在"之前卡在"一栏；D 的检查器在切人说明下写原因，全程导航也标出来；原版在表格区最前面加一张卡片，时间轴上同样标出。

展示用的归类规则（写在 `web/designs/shared.js`，不影响仿真）：等待里派生窗口、优先级、连段、同一 tick、写轴要求的算"正常节奏"（`RHYTHM`）；在任何一段命中的生效 buff 里出现过的算"影响伤害"；每秒伤害按世界秒分桶；乘区的中文名 `ZONE_NAME`。

时间轴模型（`src/report/timeline.ts` 的 `timelineModel`）为此新增两项：`buffOwners`（buff → 登记它的角色，声骸、武器、套装算穿戴者，场景 buff 记 `env`）与 `buffInfo`（buff → 乘区、每层的值（已按谐振阶取好）、层数上限、原文、过滤条件）。v0.2.3 再加 `gains`（每个动作给的资源，按出处合计）、`effectInfo`（资源型效果的原文）、`energyShare`（能量的分配比例），日志里的命中带 `owner`（归到的动作开始的实例号）、`trigger`、`via`、`note`（TD-10 §5.1）。

命令行：`pnpm timeline <场景> --view a|b|c|d|e` 写 `out/<场景名>.<视图>.html`（`TIMELINE_VIEWS`、`renderDesign`），与网页里的同一份模板与数据；不写 `--view` 是原版。v0.2.4：时间轴模型再加 `resources`、`forte`、`cooldowns`（TD-10 §5.1）。

## 3. 检查

### 3.1 v0.2.1 的修正（2026-10-12 review）

- **场景页**：结果区高度跟视口走、在框里滚动（原来按内容撑开，B 的吸顶时间轴、D 的整屏布局都失效）；可以收起编辑器让结果占满宽度；记住上次选的视图与收起状态；场景改过但没重新运行时提示；Worker 缓存最近一次仿真，切换视图不重跑。
- **修 bug**：编辑后切换视图报"postMessage 无法克隆对象"（上次运行的场景存在响应式状态里，是代理对象）；`api.ts` 发请求前统一转成普通数据。
- **页面超宽**：择优页被"写进场景"的长代码撑宽（宽屏 1735 像素、手机 1279 像素），对比页手机上宽 20 像素；网格里的卡片都可以收窄。
- **D**：检查器在 760 像素以上都放在主图右侧（原来 1000 像素以下就挪到下面，嵌在网页里约 970 像素宽时看不到）。**C**：表格在自己的框里横向、纵向滚动，"之前卡在"不再被挤成一列。
- **原版**：等待表按原因合计、卡住的在前（原来几百条逐条列出，页面高 9000 多像素）；时间轴上正常节奏的等待画成灰色；buff 行加高、标签栏加宽。
- **字体**：等宽字体的回退里加上中文字体（原来 Windows 上中文会落到系统默认字体）。
- **择优页**：5 件套可以从库存里的套装选；没有组合时说明原因；"就是现在这套"标出来。角色候选按 YAML 解析（`peek.ts`；行内写法 `- { char: 椿 }` 原来读不到）。

### 3.2 手机与 iPad（触摸屏，2026-10-12）

触摸屏没有悬停，拖动缺省是滚动，原来很多操作做不了：悬停提示、D 的光标与导航图拖动、标签上的 `title` 都看不到或用不了。现在：

- **提示**：所有悬停提示都是"鼠标悬停、触摸屏点一下"（`shared.js` 的 `tips`，原版的 `onMove`）。点一下，提示显示在手指上方；点别处或滚动就收起；拖动、滚动不算点。原来只有 `title` 的地方也改成同一种提示：A、B、原版的标签栏，C 的指令原文、前台段与 buff 覆盖，D 的 buff 出处。
- **D 的手势**：
  - 主图：点一下放光标；单指横拖移动光标（竖拖仍是滚动，`touch-action: pan-y`）；双指捏合缩放、平移视窗。
  - 导航图：横拖选范围，点一下把视窗挪过去（鼠标也一样）；右边加了 − ＋。
  - 触摸屏不分"锁定"。手势的点按归页面自己处理，不弹提示（`data-own-tap`）。
- **手机布局**（宽 ≤ 760 像素；A、B、C 是 ≤ 640 像素）：
  - D 整页滚动。主图宽度跟屏幕走（原来至少 500 像素，要横向滚动），左边标签栏收窄。底部固定一条步进条：◀、当前时刻与当前步、单位、▶；完整的上一个 / 下一个在下方步进区。
  - A、B 的标签栏从 210 / 196 像素收到 112 像素，被截断的点一下看全名。
  - B 只让刻度吸顶（原来整个顶部吸顶，占半屏），泳道图宽度跟框走（原来至少 400 像素，右边被裁掉）。
  - C 不画甘特列时，表格最小宽 560 像素。
- **网页**：
  - 结果可以"全屏"：盖满屏幕，Esc 或"退出全屏"回来；场景页与视图说明页都有。手机上视图按钮只写"原版"和字母，一行放得下。
  - 输入框、下拉框字号 16 像素（iPhone 聚焦小字号输入框会自动放大页面）；触摸屏上按钮至少 36 像素高。
  - 手机上编辑框不超过半屏；运行后结果还在屏幕外时自动滚过去。收起编辑器时，栏里可以换场景。
  - "复制"：用 http 加域名访问时不是安全来源，没有 `navigator.clipboard`，退回 `execCommand('copy')`（`clip.ts`）；再不行就提示手动复制。"下载"在 Safari 上延后收回地址。
- **小修**：
  - A、B、D 只在宽度变了时重画。手机上滚动时地址栏伸缩会发 resize，A 原来会因此把缩放打回"适应宽度"。
  - 悬停样式只给鼠标（`@media (hover: hover)`），触摸后不再残留高亮。

检查方法：在 Chromium 的设备模拟里（iPhone 13、iPad Pro 11 竖屏与横屏），用 CDP 的 `Input.dispatchTouchEvent` 发真触摸事件，逐项点过、拖过、捏合过；桌面鼠标操作也回归了一遍。没有在真机 Safari 上试过。
