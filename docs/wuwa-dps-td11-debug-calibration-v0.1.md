## 0. 要点

1. **先把"对不上"说清楚**：对不上的是什么（时长 / 资源 / 伤害 / 状态 / 报错），按哪个时钟，比的是哪一轮，参照是什么（§1）。
2. **判断出在哪一层**：轴的转写、数据、规则、假设、引擎与构建（§2）。这次的案例：转写、数据、规则、构建各一次，另有一个被否掉的规则假设（§5）。
3. **从粗到细定位**：分轮 → 分段 → 逐条 → 逐帧；资源类问题看资源逐步表（§3）。
4. **一次只改一处做实验，用数字检验**：能解释"差多少"的假设才值得追；能让轴跑通的假设不一定对（§4）。
5. **规则以用户和可信来源为准**：查证结论记进 m0-confirm，改机制要带用例，已确认的规则不反复推翻。

## 1. 先把"对不上"说清楚

### 1.1 五种对不上

| 类型 | 例子 | 先看什么 |
|---|---|---|
| 时长 | 视频说 25 秒一轮，仿真 27.15 秒 | 分段表、逐条表（§3.2、§3.3） |
| 资源 | 协奏不满，一日花放不出来 | 资源逐步表、分轮的资源首尾差（§3.1、§3.5） |
| 伤害 / DPS | 某个动作伤害偏高 | `pnpm compare` 的分动作与 buff 覆盖率，`hit` 事件的 `factors` |
| 状态 | 盛绽、含苞这类形态或 buff 该不该在 | 时间轴网页的 buff 行、事件日志 |
| 报错 | 连段接不上、等超时 | 报错写的位置（"第 k 轮第 n 条"）、等待记录 |

### 1.2 时钟

- **世界秒** = 帧 ÷ 60，包含大招、谐度破坏这类全局时停，对应视频播放器上的时间。
- **战斗秒**在全局时停时停走，对应深塔倒计时；"X 秒一轮"一般指战斗秒（m0-confirm §9.2 测5）。
- 两者差在全局时停：视频轴第 2 轮世界 35.93 秒、战斗 27.15 秒，差的 8.8 秒是三个大招和一次谐度破坏的全局时停。对照视频时间点用世界秒，对照"X 秒轴"用战斗秒。

### 1.3 比哪一轮

启动轴（第 0 轮）、第 1 轮受开局资源影响，和之后的轮不一样；稳态取第 2 轮到倒数第 2 轮（TD-10 §2）。对照前先说好比的是哪一轮。

### 1.4 参照本身也会错

- 文字轴可能漏写操作：视频轴的"协奏不够多a一下"只出现在字幕里，文字轴没有（§5.1）。
- 记号要对齐：Z 是长按，"5"是漏打的"→"，红椿里的 A 是蔓舞（`scenarios/m0-video.yaml` 开头的说明）。
- 视频是某一次的实际操作，有手速差异；校准取多轮的平均，或者以视频里最稳定的几段为准。

## 2. 出在哪一层

| 层 | 典型情况 | 怎么查 | 这次的例子 |
|---|---|---|---|
| 轴的转写 | 文字轴漏写、记号理解错、按规则推演的形态（白椿 / 红椿）和实际操作不符 | 对照视频的操作与字幕；按规则推演每一步的形态，标出需要人确认的地方 | 一日花前漏了"多a一下"（§5.1） |
| 数据 | xlsx 的数值、版本差异、没读的列 | 构建报告、两版数据对比、`pnpm check:data -- --flags` | 散华"大招-引爆冰川"协奏 0 → 15（§5.4） |
| 规则 | 仿真规则与游戏不同 | 查证（用户、可信来源）；一次改一条规则做实验 | 谐度破坏插在连段中间（§5.3）；"切人退出盛绽"是被否掉的假设（§5.2） |
| 假设 | 开局资源、能量、敌人、按键时机 | 场景的 `initial`、`options`；改一个假设看差多少 | 开局红椿·蕊按 0（§5.1） |
| 引擎与构建 | 代码 bug、读表读错 | 最小复现（人造动作）、不变量检查、两版产出逐字节对比 | 换 xlsx 版本后构建读错（§5.5） |

先怀疑转写和数据，再怀疑规则，最后才是引擎：前两层最常见、也最便宜查；规则要查证；引擎有不变量检查和全量测试兜着。

## 3. 从粗到细定位

### 3.1 分轮

`pnpm sim` 的分轮表：每轮时长、DPS、三人的能量与协奏首尾差。首尾差都是 0 说明这条轴能自给；**隔轮正负交替**说明某个资源隔一轮才够（§5.4）。

### 3.2 分段：每次上场多久

切人到下一次切人算一段。对视频只需要记切人的时刻，最容易先定位慢在哪一段。`pnpm trace <场景> --seg` 打印这张表；视频轴第 2 轮：

| 段 | 上场 | 开始（世界秒） | 世界秒 | 战斗秒 |
|---|---|---|---|---|
| 1 | 散华（变奏） | 0.00 | 5.02 | 3.52 |
| 2 | 维里奈（变奏） | 5.02 | 4.62 | 4.62 |
| 3 | 椿 | 9.63 | 1.00 | 1.00 |
| 4 | 维里奈 | 10.63 | 3.17 | 1.40 |
| 5 | 椿（变奏） | 13.80 | 5.48 | 5.48 |
| 6 | 散华 | 19.28 | 1.00 | 1.00 |
| 7 | 椿 | 20.28 | 15.65 | 10.13 |
| 合计 | | | 35.93 | 27.15 |

### 3.3 逐条：每条指令在等什么

每条指令的开始时刻、到下一条用了多久、之前在等什么（原因与帧数，TD-09 §3.3）。等待原因读法：

| 原因 | 意思 | 常见的调法 |
|---|---|---|
| 优先级 X 低于 Y 当前的 Z | 上一个动作还不能被这一招打断 | 换能打断它的招，或接受这段时间 |
| 等 Y 的派生窗口 | 连段要等上一段的派生窗口开 | 一般是正常节奏 |
| 等 Y 出手（现在打断会丢判定或延奏） | 缺省等"取消不丢东西"；`!` 可以抢帧 | 视频若明显更快，试 `!`（TD-09 §3.4） |
| 第 n 帧前不响应输入 / 不能切人 | 输入锁、切人锁 | 对照 xlsx 备注 |
| 冷却 / 资源 / 角色条件（如"一日花要协奏满"） | 状态没满足 | 看资源逐步表 |
| 切人冷却还剩 n 帧 | 两次切人至少隔 60 帧 | —— |

`pnpm trace <场景>` 在分段表后面打印这张表。视频轴第 2 轮第 7 段的几条（原型输出，现在的格式见 §6.1）：

| 条 | 指令 | 到下一条 | 之前在等（帧） |
|---|---|---|---|
| 14.4 | 椿 E3 | 3.78 秒 | 一日花要协奏满 9；等 A2 出手 13 |
| 14.5 | 椿 E1 | 1.43 秒 | E3 的优先级 63；插了谐度破坏 97；E 冷却 67 |
| 14.6 | 盛绽·A3循环聚怪 | 2.03 秒 | E1 的优先级 85 |
| 14.7 | 椿 Q·斩击 | 0.20 秒 | 等烬华蔓舞的派生窗口 122 |

### 3.4 逐帧

时间轴网页（`pnpm timeline`，TD-10 §5.1）：动作条、资源曲线、buff 区间、敌人的偏谐值与白条、失谐 / 谐度破坏 / 破盾的标记。再往下是事件日志 `out/<场景>.json`。

### 3.5 资源逐步表

资源类问题（"协奏不够"）要看资源每次怎么变：一行一次变化，列出时刻、事件、各人的值、来源（进入即得 / 逐段命中 / 钩子给的，如"每耗 10 点蕊 +4" / 延奏清零），核心资源（红椿·蕊）另起一列。视频轴的协奏问题就是靠这张表看出来的（§5.1）。`pnpm trace <场景> --res 协奏`（或 `能量`、核心资源名），`--char` 只看一个角色。

## 4. 做实验

- **一次只改一处**：把场景复制一份，改一行，跑 `pnpm sim`，或用 `pnpm compare 原场景 新场景` 看差在哪。
- **规则实验**：临时改角色模块（例：让切人退出盛绽），做完一定改回。开局核心资源不用改代码：场景里写 `initial.core: { 椿: { 红椿·蕊: 100 } }`（§6.1）。
- **用数字检验**：先算清楚差多少、要什么才补得上，再看假设能不能刚好补上。例：协奏差 2.1，蕊还剩 18.1，凑 10 点的累计已有 1.9 → 一日花前再耗 8.1 点蕊才多一次 +4。能解释差额大小的假设才值得追。
- **能跑通 ≠ 对**：假设"切人退出盛绽"能让整条轴跑通，但和用户确认的规则冲突，最后证明原因在别处（§5.2）。
- **记录**：查证的结论记进 m0-confirm（谁确认、依据是什么）；改机制带用例；场景快照的变化人工确认后再更新。

## 5. 案例

### 5.1 视频轴的一日花放不出来（资源，转写层）

- **现象**：按文字轴推演（AAAAAE 是蔓舞 + E2），走到"椿REE"时协奏 97.9 / 100，一日花等到超时（启动轴，开局红椿·蕊按 0）。
- **查法**：资源逐步表（三人的协奏 + 椿的红椿·蕊）。变奏给的 100 点蕊只耗掉 81.9，一日花时还剩 18.1 点，被一日花回满吃掉；差的 2.1 只要再多一次"耗 10 点蕊 +4"就够。试过开局蕊给 100：启动轴能过，循环第 1 轮仍差 4.9，说明不是开局蕊的问题。
- **结论**：视频在一日花前有字幕"协奏不够多a一下"，文字轴漏写了这一下。写成补位 `A1~ A2~`（只在一日花放不出来时才打）；仿真里有的轮要两下（大招后白椿 A1 只回 1.85，凑不凑得上 +4 看余数）。
- **记在**：m0-confirm §11 V2；AGENTS.md 差异 1。

### 5.2 "切人退出盛绽"：能跑通、但被否掉的假设（规则）

- **现象**：用户先说启动轴里的 AAAAA 是白椿，按现在的规则推演只能是红椿。
- **实验**：假设切人退出盛绽 → AAAAA 是白椿 5 段（耗蕊 85.2）+ E1（21.1），整条轴跑通。
- **结论**：用户确认切人不退出盛绽，"如果有对不上绝对不是这个原因"，这个假设否掉；真正的原因是 §5.1。教训：能让轴跑通的假设不一定对；已确认的规则不要反复推翻，先回到转写和数据。
- **记在**：m0-confirm §6 C1、§11 V1。

### 5.3 自动谐度破坏把连段拆断（报错，规则）

- **现象**：视频轴第 2 轮的"闪AAAEQ"报"盛绽·A2 只能接在 盛绽·A1 之后"。
- **查法**：看报错前后的事件：盛绽·A1 命中让目标失谐，自动谐度破坏插进来取消了 A1。
- **结论**：查证谐度破坏会打断当前角色的任何动作（17173；用户信任的 B 站视频），仿真按规则没错；改的是自动插入的时机：队首是连段后续时先不插（TD-09 §3.2、TD-06 §13.4）。顺带从 xlsx 附页2 查出谐破冷却、按钮、削白条的规则（m0-confirm §10）。
- **记在**：m0-confirm §10 H1。

### 5.4 散华隔轮才变奏（资源，数据层）

- **现象**：分轮表里散华的协奏首尾差 −73 / +85 / −85 / +85 交替：散华切维里奈只有隔一轮是变奏。
- **查法**：看每次切人时散华的协奏（73、85、100…）。
- **结论**：数据版本差异。20260707 版散华"大招-引爆冰川"不给协奏，20261003 版给 15；换版后每轮都变奏，和视频一致。
- **记在**：AGENTS.md 差异 7（已并回）；m0-confirm 开头。

### 5.5 换 xlsx 版本后构建读错（引擎与构建）

- **现象**：新版构建报"成长表里没有 90 级"；golden 有 1652 格认不出；谐度破坏与异常效应的格判反（abnormal 173 ↔ tune 30）。
- **查法**：两版 `base` 页第 55 行表头逐列对比 → O 列后插了一列；`伤害计算` 的标记行整体下移 88 行；`伤害配置` 的段名下移 117 / 119 行。
- **结论**：改成按表头、标记行、段名定位；用"旧版产出逐字节不变"做回归，新版 golden 按 TD-03 重算全等。
- **记在**：TD-01 §1.9。

### 5.6 一轮比视频长 2 秒（时长，未结）

- **现象**：视频标题"25s循环轴"，仿真每轮战斗 27.15 秒（世界 35.93 秒）。
- **已有**：分段表与逐条表的原型（§3.2、§3.3）。
- **下一步**：按 §6.3 在场景里记视频第 2 轮各次切人的时刻（可以交给 AI agent 看视频填），`pnpm trace` 按段对照，找到"本段差"最大的段再看逐条。可能的原因：预输入（输入缓存）没建（总设计 §13）、派生窗口与优先级、切人锁、"等出手"比实际手法保守。

## 6. 工具

### 6.1 现有

| 工具 | 看什么 |
|---|---|
| `pnpm sim <场景>` | 汇总、分轮（时长、DPS、能量 / 协奏首尾差）、不是写轴要求的等待（按原因）、跳过的指令、报错位置；事件日志写到 `out/<场景>.json` |
| `pnpm trace <场景> [--loop k] [--seg] [--res 协奏 \| 能量 \| <核心资源名>] [--char 角色] [--md] [--out 文件]` | 某一轮（缺省稳态第一轮，启动轴是第 0 轮）的分段、逐条，或资源逐步表；时刻从本轮开始算，世界秒与战斗秒都给；场景有 `video` 且是这一轮时，分段与逐条多"视频""累计差""本段差"三列，开头一行小结；`--md` 另写 `out/<场景>.trace.md` |
| `pnpm timeline <场景>` | 时间轴网页：动作条、资源曲线、buff、敌人量表、失谐 / 谐度破坏 / 破盾（TD-10 §5.1）；下方"调试表"跟着"范围"选的轮次显示同 `trace` 的几张表，点一行在时间轴上高亮；有 `video` 时多一行"视频对照"（△ 视频、● 仿真，连线红 = 本段仿真慢、绿 = 快） |
| 场景 `initial.core` | 开局核心资源：`{ 角色: { 资源名: 值 } }`，缺省 0；不在队伍、没有这个资源、超过上限都报错（TD-06 Q7） |
| 场景 `video` | 视频时间点，写法见 §6.3 |
| `pnpm compare A B` | 两次运行按角色、动作、buff 覆盖率、面板拆差额（TD-10 §3） |
| `pnpm marginal <场景>` | 副词条边际（TD-10 §4） |
| `pnpm check:data -- --flags`、构建报告、`pnpm golden:perturb` | 数据与公式层 |
| `docs/m0-confirm.md` | 规则与数据的确认结论 |

这次排查时另写过的临时脚本（协奏逐步表、逐条时间表、分段表）已经做成 `pnpm trace`。几张表都从事件日志算（`src/engine/trace.ts`），不改仿真。

`trace` 的几个约定：

- **一轮的范围**：从本轮的 loop 事件到下一轮的；本轮最后一条（常是切回）恰好落在下一轮开始那一帧时，按指令所属的轮次算进本轮。
- **等待**：记在指令名下，同一原因合计（原因里的数字不同也算同一种，如"切人冷却还剩 n 帧"）；切人带变奏时只挂在第一行。
- **插队与跳过**：自动插入的谐度破坏记作"（插队）"，跳过的可选 / 补位记作"（跳过）"，都单独占一行。
- **资源逐步**：从开场按日志重放（命中的 gains 是实际增减，资源事件给出变化后的值），只列本轮；来源写"命中""施放（进入即得）""扣除""角色钩子""破盾回能""延奏清零"或"效果 <id>"。

### 6.3 视频时间点怎么记

先按简单的来：只记一轮里若干条指令在视频里**开始**的时刻，有必要再细化。写进场景（可以是复制出来的一份）：

```yaml
video:
  url: https://www.bilibili.com/video/BV…   # 只作记录
  loop: 2                                   # 对照第几轮（缺省 2；0 是启动轴）
  marks:                                    # 键：rotation 第几条（从 1 数，空行与注释行也算一条）；值：播放器时间
    1: "1:02.5"                             # "分:秒"或秒数
    3: "1:07.1"
    9: 75.2
```

- **记哪些**：切人的那几条最好（按段对照，§3.2）；有疑问的段再补段内的几条。不用每条都记。
- **时刻取什么**：这条指令的动作开始的那一刻：切人取新角色出现（变奏入场）的那一刻，出招取动作开始。看不准时宁可少记。
- **起点**：从最早的那个时间点起算，不用对齐开场；视频里不是从轮首开始也行。
- **时钟**：视频播放器的时间包含大招与谐度破坏的时停，对照的是世界秒（§1.2）。
- **给 AI agent 的说明**：输入是视频链接、场景文件与要对照的轮次；输出是上面的 `video` 段（只填看得清的条目），附一句每个时间点的依据（如"字幕'切维里奈'出现"）。填完跑 `pnpm trace <场景> --md`，把 Markdown 和视频链接一起交回。
- **读结果**：累计差 = 仿真 − 视频（正数 = 仿真慢）；本段差 = 比上一个时间点多出来的。先看本段差最大的段；本轮没有出现的条目单列。
