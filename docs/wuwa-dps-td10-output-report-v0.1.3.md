## 0. 要点

1. 所有数字都从事件日志派生（总设计 §3.5），不在别处重算。
2. **稳态取完整的轮**：第 2 轮到倒数第 2 轮。第 1 轮受开局资源影响，最后一轮没有下一轮的边界、偏高（§2）。
3. **对比**：把场景改几处、各跑一次再做差；有分轮时比稳态，"差在哪"按窗口内的**每秒伤害**拆到角色与动作，再看 buff 覆盖率与面板（§3）。
4. **副词条边际**：每种副词条各加一档（缺省各档平均）、重跑比稳态 DPS（§4）。轴是固定的。

## 1. 汇总 `Summary`

| 字段 | 含义 |
|---|---|
| `totalDamage`、`windowFrames`、`dps` | 统计窗口内的总期望伤害、窗口长度（战斗帧）、DPS = 伤害 ÷ 窗口秒数 |
| `overflowDamage` | 窗口外仍在结算的伤害（残留的领域、召唤物），不计入 DPS |
| `byChar`、`byAction` | 窗口内按角色、按动作（角色 + 动作 ID）的伤害与占比 |
| `resourceTimeline` | 每 `rules.sampleInterval` 个世界帧采一次三人的能量与协奏（TD-06 §6.1） |
| `buffUptime` | "buff→目标" → 窗口内存在的比例（TD-07 §10.1） |
| `waits` | 不是写轴要求的等待（TD-09 §3.3） |
| `warnings` | 装配与仿真中的提示 |
| `perLoop?`、`steady?` | 分轮与稳态（§2，`options.repeat ≥ 2` 或有启动轴；v0.1.2：启动轴是第 0 轮，记为"启动"） |
| `enemy`（v0.1.1） | 窗口内失谐、谐度破坏命中、白条打空的次数，与谐度破坏的伤害（TD-06 §14） |
| `skipped`（v0.1.1） | 跳过的可选指令（排轴里写了 `?`，TD-09 §3.2）：第几轮第几条、原因 |

**统计窗口** = [第 0 帧, 最后一条指令的完成时刻)（TD-09 §3.9），按战斗帧；`options.endAt` 可覆盖。战斗帧 < 窗口终点的伤害计入，其余是窗口外。

## 2. 分轮与稳态

- **每一轮** = [本轮 `loop` 事件, 下一轮 `loop` 事件)；最后一轮到统计窗口终点（TD-09 §3.7：等下一轮起手的时间算在上一轮里）。
- `perLoop[k]`：`loop`、`start`（战斗帧）、`frames`、`damage`、`dps`，三人的 `energyDelta`、`concertoDelta` = 下一轮开始时（最后一轮：窗口终点）− 本轮开始时。资源按日志从初始值重放（同 `resourceTimeline`）。首尾差都是 0 说明这条轴能自给。
- `steady`：第 2 轮到倒数第 2 轮合起来的伤害 ÷ 时长（`from`、`to`、`frames`、`damage`、`dps`）；只有 2 轮时取第 2 轮。
- **启动轴**（v0.1.2，TD-09 §3.7）：场景写了 `opening` 时，它是第 0 轮（"启动"），照样列进 `perLoop`；稳态只看循环轴的轮（第 2 轮到倒数第 2 轮；循环轴只有 1 轮时没有稳态，只给 `perLoop`）。
- **为什么不取最后一轮**（总设计 v0.1.5 原写"稳态以最后一轮为准"）：最后一轮没有下一轮的边界，等能量、等冷却、轮首的 `wait` 都算不进来，DPS 偏高。M0 代表轴循环 4 轮（v0.1 时）：第 1 轮 25,238，第 2、3 轮都是 26,061（资源首尾差 0），第 4 轮 26,722。M4 之后（v0.1.1，带谐度破坏与破盾）：第 1 轮 27,965，第 2、3 轮都是 28,939，第 4 轮 27,123（第 4 次失谐时轴已放完，没有谐度破坏）；第 2、3 轮椿的能量首尾差 ±4.3，是破盾回能落在第 2 轮。谐度破坏按 xlsx 附页2 调整后（v0.1.2：谐破冷却 4C 3 秒、按钮、不拆连段）：第 1 轮 27,965，第 2、3 轮 29,367 / 29,369，第 4 轮 30,032。椿首位换梦魇·无冠者、Q 挪位后（v0.1.3，AGENTS.md 差异 3）：第 1 轮 29,878，第 2、3 轮都是 31,023，第 4 轮 29,079（每轮 31.77 秒，最后一轮 32.48 秒）。
- **写法**：轴的结尾要回到第 1 轮开头的局面（M0 代表轴结尾 `switch 维里奈`），`options.repeat` 4 左右、`maxFrames` 相应放大。

## 3. 对比 `compareRuns`

**口径** `basisOf`：有分轮取稳态，否则取整个窗口；记为 [lo, hi)（战斗帧）。

**差在哪**：

| 项 | 怎么算 |
|---|---|
| DPS | 对比 − 基准，及百分比 |
| 分角色、分动作 | 窗口内的**每秒伤害**（伤害 ÷ 窗口秒数），同一个窗口里加起来就是 DPS；两边窗口长短不同（换了声骸、轴变快）也能比。按差额绝对值排序 |
| buff 覆盖率 | 各自的窗口内算（`buffUptime(log, lo, hi)`），标记型 buff（计时、状态）不列 |
| 面板 | 攻击、暴击、暴伤、共鸣效率（含常驻的共鸣效率 buff）；常驻的其他 buff 在命中时才叠，不在面板里 |

**命令**：`pnpm compare 基准.yaml 对比.yaml`。打印两边的口径与 DPS、差额，变化了的面板，分角色、分动作（差额前 12）、buff 覆盖率（差 ≥ 1 个百分点，前 12）。场景有错或运行出错时退出码 1。

例（2026-10-05，v0.1.3）：视频轴 `scenarios/m0-video.yaml` 一日花前的补位 `A1~ A2~` 换成固定打两下 `A1 A2`，稳态 DPS 30,458 → 31,312（+2.80%），两边每轮都是 27.15 秒：这条轴有空余，多打的 A 不占时间。差额几乎都在椿：延奏每秒 +672（固定两下时每次切走都还在含苞里，延奏都打含苞 + 含苞追加；补位时有一轮切走时含苞已结束，只打普通版）、A2 +164。

旧例（v0.1.2，M0 代表轴当时的配装）：椿首位异相·无妄者换梦魇·无冠者（词条不变），稳态 DPS 29,368 → 32,706（+11.4%）：首位加成湮灭 / 普攻各 +12%（覆盖率 0 → 100%），它的 Q 只要 39 帧（无妄者 123 帧）；轴变快后失谐落到维里奈在前台的时候，谐度破坏从椿放变成维里奈放。代表轴 2026-10-05 已换上用户实际的无冠者（词条不同、Q 挪位，稳态 31,023），这个例子不再对应现在的场景。

## 4. 副词条边际 `marginal`

- **一档**：`echo-stats.json` 的 `subTiers`（TD-01 §12.6），缺省取各档平均（比例取到 0.0001，固定值取整：暴击 8.4%、暴伤 16.8%、攻击% 9.0%、攻击 +50、生命 +450…），`--tier max` / `min` 取最高 / 最低档。
- **加在哪**：该角色**最后一件声骸**的副词条上（不动首位；场景必须至少有一件声骸）。
- 13 种副词条各重跑一次，按 DPS 增加从大到小排。
- **轴是固定的**：共鸣效率只在原来要等能量时才有收益；"效率够了能把轴排得更紧"要改轴，属于轴搜索（总设计 M7）。只影响队友 buff 的角色（维里奈），自己的副词条收益很小是正常的。
- **命令**：`pnpm marginal 场景.yaml [--char 角色] [--tier avg|max|min]`，不写 `--char` 时三人都算。M0 代表轴（4 轮）每次约 0.3 秒，一个角色 14 次。
- 例（2026-10-05，M0 代表轴，椿，v0.1.3 重算）：暴伤 +5.59% > 暴击 +4.31% > 攻击% +2.58% > 普攻加成 +2.13% > 攻击 +1.38% > 共鸣解放 +0.33%；共鸣技能、重击加成为 0（她的 E、重击打的是普攻伤害），共鸣效率为 0（这条轴不等能量）。换上主词条暴击 22% 的无冠者后暴击已到 90%，暴伤反超暴击（v0.1.2 时暴击 +5.73% > 暴伤 +4.21%）。

## 5. 命令行

| 命令 | 输出 |
|---|---|
| `pnpm sim 场景.yaml [--out 日志.json]` | 队伍面板、敌人（v0.1.1：偏谐值上限、白条、瘫痪、谐度破坏的模式）；窗口、总伤害、DPS（窗口外伤害）；敌人量表（v0.1.1：失谐、谐度破坏的次数与伤害占比、破盾次数）；分轮表（循环时）；分角色、分动作；不是写轴要求的等待；跳过的可选指令（v0.1.1）；提示；事件日志写到 `out/<场景名>.json` |
| `pnpm compare 基准.yaml 对比.yaml` | §3 |
| `pnpm marginal 场景.yaml [--char 角色] [--tier …]` | §4 |
| `pnpm timeline 场景.yaml [--out 网页.html] [--fragment]` | v0.1.2：时间轴网页（§5.1），写到 `out/<场景名>.html` |
| `pnpm trace 场景.yaml [--loop k] [--seg] [--res …] [--char 角色] [--md] [--out 文件.md]` | v0.1.3：调试表——某一轮的分段、逐条，或资源逐步；场景有 `video` 时对照视频（TD-11 §6） |

共用的读场景、对齐、数字格式在 `src/cli/format.ts`。退出码：0 成功；1 场景有错或运行期报错；2 用法错误。`pnpm sim` 的分轮表里启动轴记为"启动"，等待与跳过写"启动第 k 条"（v0.1.2）。

### 5.1 时间轴网页（v0.1.2，M6 第一步）

- `web/timeline.html` 是模板：一个文件，自带样式与脚本，不用构建；直接打开时可以选 `pnpm sim` / `pnpm timeline` 写出的 JSON。
- `pnpm timeline 场景.yaml`（`src/cli/timeline.ts`）跑完仿真，把结果与画图要的元数据（队伍、能量上限、敌人量表、排轴原文（含启动轴）、各动作的类别）嵌进模板，写 `out/<场景名>.html`；`--fragment` 不带 `<!doctype>` 与 `<head>`，给要再包一层的地方用。场景出错时网页照样写出，日志保留到出错为止。
- 画的是事件日志本身：各角色的动作条、能量与协奏曲线、buff 区间、敌人的偏谐值与白条（`hit.enemy`，TD-02 §7.3）、失谐 / 谐度破坏 / 破盾的标记，与 §1、§2 的汇总。
- v0.1.3：**调试表**——网页下方跟着"范围"选的轮次（缺省稳态第一轮，没有稳态时第 1 轮）显示分段、逐条与资源逐步表（与 `pnpm trace` 同一份数据：`timelineModel` 多 `trace`，每轮一份），点一行在时间轴上高亮那一段并滚过去。场景有 `video` 时多一行"视频对照"（△ 按视频推算的位置、● 仿真里的位置，连线红 = 本段仿真慢、绿 = 快；`timelineModel.video`），调试表多视频、累计差、本段差三列（TD-11 §6.3）。
- 排轴编辑、场景编辑留给 TD-12。
